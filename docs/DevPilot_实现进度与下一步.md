## 3. 下一步开发顺序

1. **安全与执行基线并行补齐**：统一 RequestSpec/出站策略，建立持久运行与逐条不可变观测；未满足的 I0 门禁不能靠 UI 绕过。
2. **项目 + 数据深化**：在已做的本人项目/QA自审冻结基础上，关联提测/组件版本与冻结执行引用，补独立审核/质量卡；先做可验证数据，再接自动构建 Agent。
3. **逐条人工复核**：组件版本、输入 Q、实际 A、预期/容差、来源和技术错误同屏；保留自动判定与人工决定，不能覆盖原始响应。
4. **运行 → 复核 → 项目报告**：引用不可变平台结果而非手抄，模板版本与报告修订持久化，再推进批准的 DOCX/PDF。
5. **脚本导出、整改复测与知识闭环**：在前述事实/权限/版本基础上增量实现，再开放多模型自动分工。

I5 中的定时评测和有界多轮对话已局部前移，但不代表 I0/I1 或 I5 整体完成。先把一条可复现、可复核的 QA 评测纵切面跑通，再扩展 CV 和更深自动化。
