# DevPilot 实现进度与下一步

日期：2026-11-07。本文记录当前代码边界，不是目标功能清单的完成声明。只有通过对应验收门槛才能更新里程碑；不使用缺少分母的“完成百分比”。

## 1. 本轮交付

- 评测优先入口：/workspace 默认进入 /workspace/evaluations，组件测试、定时评测、报告、模型连接为主导航；聊天作为辅助能力保留。
- 模型连接档案：借鉴 CC Switch 的预设、连接管理与切换思路，分离服务商标签、协议、地址、模型 ID、受控参数和角色用途。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini Developer API 四类协议，不把客户端种类当成协议数量。
- 报告需求多轮：页面显示往返消息，逐轮补充/修正，最多 10 轮、序列化上下文不超过 24000 字符，每次重新授权。只确认基础字段，不能修改测量事实。
- 这些是工作台切片，不表示已经完成自动化评测 Agent 全流程。

## 3. 下一步开发顺序

1. **安全与执行基线并行补齐**：统一 RequestSpec/出站策略，建立持久运行与逐条不可变观测；未满足的 I0 门禁不能靠 UI 绕过。
2. **项目 + 数据最小闭环**：项目/提测版本、授权来源、人工导入与校验、样本/金标分离、审核冻结；先做可验证数据，再接自动构建 Agent。
3. **逐条人工复核**：组件版本、输入 Q、实际 A、预期/容差、来源和技术错误同屏；保留自动判定与人工决定，不能覆盖原始响应。
4. **运行 → 复核 → 项目报告**：引用不可变平台结果而非手抄，模板版本与报告修订持久化，再推进批准的 DOCX/PDF。
5. **脚本导出、整改复测与知识闭环**：在前述事实/权限/版本基础上增量实现，再开放多模型自动分工。

I5 中的定时评测和有界多轮对话已局部前移，但不代表 I0/I1 或 I5 整体完成。先把一条可复现、可复核的 QA 评测纵切面跑通，再扩展 CV 和更深自动化。
