# DevPilot 评测数据构建与执行工作流

> **DAT-03 当前实现补充（2026-11-21）**：工作区源码已实现 owner-scoped 批次/清单元数据、PostgreSQL migration、单附件受控上传、有界确定性解析及显式同意的一次性预览 POST。TXT/Markdown 按行，JSON/JSONL 按文档或记录，CSV 按行，DOCX 按段落/表行，XLSX 按工作表/行/单元格范围，PDF 按页/文本块；损坏、加密、超限或无可选文本时整体阻断且不返回部分结果；JPEG/PNG/WEBP 因 OCR 未配置明确阻断。解析文本不持久化；仅保存 parser 版本、状态、结果 hash、块数、安全原因和无正文 receipt，组件状态仅汇总为 `parsed/blocked`。预览重验附件 SHA-256、字节数、owner、上传状态和 retention，明文仅按一次请求返回且 `private, no-store`。批次 UI、候选生成、审核和归档仍未实现；本轮完整 Linux/PostgreSQL 门禁完成前不代表验收或部署。

## 产品流程

核心流程为：材料包 → 项目外构建批次 → 按组件生成候选用例 → 归档到一个已有或新建项目 → 评测人员浏览、审核并冻结数据版本 → 计划选择组件适用的数据版本 → 将用例输入解析成该组件请求格式 → 受控发送请求并保存原生响应 → 按可用证据和规则评估。

产品角色仍为评测人员和管理员，不增加独立的数据构建或审核角色。项目归属、任务指派及具体运行中的职责分离继续适用。

## 材料包与构建批次

材料包包含组件清单及关联附件。清单至少描述稳定组件标识、组件名称和类型、业务用途、输入/输出示例，以及关联附件标识。附件可以属于一个组件或项目级共享材料；系统不能根据文件名猜测归属，无法确认时应要求评测人员映射。

构建批次可在项目创建前存在。一个批次归档到一个项目；归档时可选已有项目或新建项目。批次中的每个组件分别形成数据候选，项目级附件可被多个组件引用，但来源和转换记录保持可追溯。清单组件总数是处理分母；无法解析、构建失败或明确排除的组件均须显示状态和原因，不能静默丢弃。

用户上传文件或知识库导出包，不向服务端传本机路径并期待服务器读取。首期格式边界为 DOCX、PDF、XLSX、CSV、TXT、Markdown、JSON 和 JSONL；脚本仅作文本材料解析，绝不执行。压缩包必须安全检查。扫描版/加密/损坏/不支持的附件应列出文件和失败原因，提示人工提取或补充；未实现 OCR 或知识库连接器时，不宣称能够自动读取。

当前 DAT-03 上传 API 为 `POST /api/evaluation/material-batches/{batch_id}/attachments/{artifact_id}`，一次接收一个附件；附件须先在批次 manifest 中声明文件名、授权依据、用途、敏感级别和带时区的未来保留期限。当前扩展名白名单为 CSV、DOCX、JPEG/JPG、JSON/JSONL、Markdown、PDF、PNG、TXT、WEBP、XLSX。服务端按配置的大小上限及 multipart 总体预算限制请求体，使用生成 ID 写入显式配置的 artifact root，计算原始字节 SHA-256 并原子发布；相同字节重试幂等，冲突内容拒绝。上传 API 仅返回安全元数据，不提供文件字节读取路由。批次元数据路由和上传均限制为登录人类用户的 owner 范围；过期 retention、内部 Agent 和跨 owner 访问拒绝。一次性预览 API 为 `POST /api/evaluation/material-batches/{batch_id}/attachments/{artifact_id}/preview`，请求必须含 `open_content=true` 与 operation UUID；`GET /api/evaluation/material-batches/previews/{operation_id}` 只返回不含正文的回执。解析正文不落库，操作 UUID 不重放明文；用户界面仍须在导航/卸载时清除暂存内容。当前源码不代表生产部署或导入闭环完成。

以上格式定义的是来源材料提取范围，不等于所有内容都能自动转成被测组件输入。用例输入须经对应组件/任务类型的版本化 adapter 转成请求字段；图像、视频、结构化 CV 标注、多轮 Agent 轨迹等需要专用数据 schema 和 adapter。没有已验收 adapter 时应阻止自动转换并要求人工整理，不能把抽取到的文本冒充完整多模态测试集。

导入解析保留源文件 SHA-256、版本、授权用途、敏感级别、保留期限和可定位的页/工作表/行/段落位置。材料是非可信输入，不能执行其中脚本、宏或指令。发送材料到模型属于单独的数据外发授权；默认不外发，内网模型也需使用明确配置的连接。

## 候选生成与质量检查

确定性解析器先提取可读文本和结构化附件，生成按组件归属的提取预览及缺项报告。评测人员确认组件映射和授权范围后，Agent 才能在预算内为各组件提出候选输入、调用字段映射和可选参考答案建议。系统记录来源定位、真实/合成/公开基准类型、模型/提示/规则版本、生成时间及人工修订历史。

候选输入、候选参考答案和正式参考答案分开保存。材料里的示例输出或 Agent 生成的答案都不能自动成为金标。没有参考答案的用例仍可构建；它可以用于请求执行、原生响应采集、性能测量，或依据已批准的 schema、规则、rubric 和人工判断评估。

每条用例显式记录 reference_status：not_provided、candidate、approved 或 rejected。not_provided 是合法的数据状态，不等于样本无效；只有 reference_status=approved 的参考答案可供 reference 对比指标使用。用例本身的审核状态与参考答案状态分开管理。

Reference 状态、revision/hash、审批和授权可见性由[数据集与指标规范](DevPilot_数据集与指标规范.md)定义。本工作流只定义迁移顺序：旧 expected 缺少独立审批证据时不得直接提升为 approved；新评测须创建 candidate reference revision 并完成审核。历史 v1 dataset/plan/run hash 原样只读校验，不重算或覆盖；旧报告保留 legacy 解释。reference 可选时不阻断已授权采集，也不将采集成功认作评估通过。

质量门禁确定性检查结构、字段映射、重复/近重复、敏感信息、授权、覆盖、来源/主体/时间泄漏及数据分布。质量检查报告和人工审核决定分开记录。缺失或有歧义的来源证据、输入映射、标签和授权形成阻断或待人工处理项，不由 Agent 自行补成已验证事实。

## 归档、审核与冻结

归档把批次及各组件的候选结果关联到一个项目，生成项目下的待审核数据草稿和不可变来源/构建记录；归档不代表审核通过、批准或冻结。已有项目中的组件应显式映射到现存项目组件；缺失组件须由评测人员确认后新增关联，不能按相似名称自动合并。

评测人员可按组件浏览批次、解析报告、来源定位、候选用例、可选参考答案和质量问题，并修订或拒绝候选。数据审核在项目内完成。审核通过后冻结新的数据版本；冻结后不可变，修订必须创建新版本。归档或审核未完成的数据不能被执行计划选择。

## 执行与评估

评测人员可从已冻结数据版本中选择，或导入新材料/数据文件进入同一解析与候选审核流程。新导入不能绕过归档、组件适配检查和审核直接运行。执行计划绑定项目、组件、RequestSpec 版本、数据版本 ID/revision/hash、输入映射、测试范围、预算和适用评估规则。服务端必须确认数据版本确实适用于所选组件；同项目本身不足以证明组件兼容。输入数据通过冻结的声明式映射解析成组件请求，不执行 Agent 生成代码，也不把参考答案传给被测组件。

缺少 expected/参考答案**不阻止解析、请求发送或原生响应留存**。执行层保存未被语义改写的响应原件及其 hash、HTTP 状态、错误和时延等技术观测；敏感内容按权限加密/受控访问，凭据和不必要的响应头不得泄露。

执行状态与评估结论分离。可用的评估方式包括确定性 schema/规则检查、按已批准 rubric 的裁判评估和人工复核。基于参考答案的精确/语义对比指标在没有经审核参考答案时为 UNAVAILABLE；所需证据缺失时不得 PASS。无参考答案但已有其他充分且预先冻结的评估依据时，可据此评估；没有任何适用依据时评估结论为 NOT_EVALUATED，缺少方案声明的必需证据时为 BLOCKED，已有人工/裁判评审仍未完成时为 PENDING。上述情况都允许保留调用和观测结果，但不得将采集成功写成效果通过。

效果和性能计划可选择同一组件数据版本，但分别冻结适用指标、分母、预算和判定条件。性能测量不依赖 expected；重复请求不能改变用例分母。若要只测部分用例，需将精确 case ID 集合及 hash 冻结为范围，不能运行后挑选成功样本。

## 对现有系统的演进

- 保留现有项目、组件、数据版本、RequestSpec、计划和执行身份链；冻结数据的 ID/revision/hash 继续作为执行快照基础。
- 新增项目外材料批次、源文件/artifact、组件清单、解析记录、逐组件构建状态、候选数据和归档关联；文件字节放受控 artifact 存储，数据库保存授权、定位、状态和 hash。
- 现有 JSON/JSONL 导入作为人工构建入口继续保留。已部署基线的 QA sample 要求非空 expected；工作区 DAT-02 候选允许 expected 缺省/null，并允许无 reference 样本进入授权执行，但候选尚未提交、完整签核或部署。候选目前只将 expected 文本移入独立表，尚无 reference 状态、独立审批/修订/hash；其 dataset hash 仍含 expected。目标 v2 必须拆分输入/reference hash 与 revision，并在 plan、评估及授权展示处验证 approved 状态；旧 hash 仅走 v1 只读兼容，不隐式批准历史答案。
- 扩展项目组件与数据集的适用范围校验，并使提测版本/执行计划引用对应组件的数据快照。计划选择器只展示审核冻结且兼容的数据版本。
- 前端增加构建批次向导、组件级进度和归档后数据审核视图；现有项目数据浏览/冻结和执行计划页面逐步接入。
- App 负责权限、作业状态、项目归档、事务、审计和不可变版本；Harness/LangGraph 负责受限的材料理解和候选建议；解析、校验和计量由确定性服务执行。Agent 不直接改业务表、不执行上传脚本、不批准数据。

本合同不表示任何上述新流程已经实现。实施应先覆盖合成材料、格式边界、无 expected 执行、原生响应证据、组件错配阻断和失败恢复，再经批准的真实材料验收。
