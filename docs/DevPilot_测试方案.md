# DevPilot 测试方案 v1.0

## 0. 文档说明

本文档定义 DevPilot 的测试策略、测试层次、关键测试用例与验收标准。DevPilot 的核心挑战在于 **Agent 输出不确定**，因此除常规软件测试外，必须建立 **Agent 评测** 与 **沙箱安全** 两套专门测试体系。

## 1. 测试策略总览

| 测试层次 | 目标 | 工具 | 触发时机 |
| --- | --- | --- | --- |
| 单元测试 | 函数/模块正确性 | pytest / vitest | 每次提交 |
| 集成测试 | 模块间接口 | pytest + testcontainers | 每次 PR |
| E2E 测试 | 端到端流程 | Playwright | 每日/发布前 |
| Agent 评测 | Agent 任务成功率与质量 | 评测集 + LLM-as-Judge | 每次模型/Prompt 变更 |
| 沙箱安全测试 | 隔离与逃逸防护 | 攻击用例集 | 每次沙箱变更 |
| 性能测试 | 延迟/吞吐 | Locust / k6 | 发布前 |
| 成本回归测试 | 单任务 token 成本 | 统计脚本 | 每次模型变更 |

## 2. 单元测试

### 2.1 覆盖范围

- 后端：状态机（task/approval）、模型路由、token 计算、工具接口、RAG chunk 切分、评测字段校验
- 前端：组件渲染、状态管理、SSE 解析

### 2.2 关键用例

- 任务状态机合法迁移（CREATED→RUNNING→PAUSED→RUNNING→SUCCESS），非法迁移被拒绝
- 审批超时默认 reject
- token 上限触发后任务终止
- 评测 7 字段校验（范围、必填、类型）

## 3. 集成测试

### 3.1 覆盖范围

- API ↔ Agent Runtime（任务创建→执行→评测→报告）
- Agent ↔ 沙箱（工具调用）
- Agent ↔ Milvus（RAG 检索）
- Agent ↔ Redis（短期记忆/checkpoint）

### 3.2 关键用例

- 创建任务→启动→SSE 推送→完成，全链路
- Checkpoint 恢复：中断后从检查点继续
- 模型路由：不同节点命中不同模型
- 多租户隔离：用户 A 无法访问用户 B 的任务/文件

## 4. E2E 测试

关键用户旅程（Playwright）：

1. 注册→登录→创建项目→创建任务→启动→查看实时过程→审批→查看评测报告→下载文件
2. Bug 修复任务：上传仓库→修复→查看变更
3. 任务失败→查看错误→重新启动

## 5. Agent 评测（核心）

### 5.1 评测集构建

构建带标准答案的任务集，覆盖 4 种任务类型，每类至少 50 个任务：

| 任务类型 | 评测集示例 | 验收指标 |
| --- | --- | --- |
| fullstack_gen | "生成含 CRUD 的用户管理 API" | 可运行 + 测试通过 |
| script_gen | "写一个 CSV 清洗脚本" | 输出正确 |
| code_review | "审查这段代码的安全漏洞" | 命中已知问题 |
| bug_fix | "修复登录模块 NPE" | 测试通过 |

### 5.2 评测指标

- **Task Success Rate**：任务端到端成功率（目标 ≥ 70%）
- **Compilation Pass Rate**：代码可编译率（目标 ≥ 90%）
- **Test Pass Rate**：自动测试通过率（目标 ≥ 70%）
- **Hallucination Rate**：幻觉率（目标 < 5%）
- **7 字段评测**：taskScore / codeScore / testScore / hallucinationRate / confidence / overall / report

### 5.3 评测流程

```text
评测集 → Agent 执行 → 结果采集 → LLM-as-Judge 评分 → 指标统计 → 报告
```

### 5.4 回归触发

- 模型切换/升级
- Prompt 版本变更
- 工具集变更
- 每次发布前

## 6. 沙箱安全测试（最高优先级）

### 6.1 攻击用例集

| 类别 | 测试用例 |
| --- | --- |
| 逃逸 | 尝试访问宿主机文件系统 /proc、/sys、docker.sock |
| 网络 | 尝试访问内网/元数据服务（169.254.169.254） |
| 资源 | fork 炸弹、内存耗尽、CPU 打满 |
| 提权 | sudo、setuid、capability 利用 |
| 文件 | 写宿主关键路径、符号链接攻击 |
| 超时 | 死循环、sleep 长时间 |

### 6.2 验收标准

- 所有逃逸用例必须失败（沙箱拦截成功）
- 资源耗尽被限额拦截，不影响宿主机与其他租户
- 超时机制生效，任务被强制终止

### 6.3 测试方式

- CI 中自动运行攻击用例集
- 定期手动渗透测试
- 沙箱配置（gVisor/Firecracker）变更后强制重跑

## 7. 性能测试

| 指标 | 目标 | 工具 |
| --- | --- | --- |
| API 响应（非 Agent） | P95 < 200ms | Locust |
| SSE 首字节 | < 500ms | 自研脚本 |
| 沙箱创建 | < 5s | 压测 |
| 并发任务 | 100 并发稳定运行 | k6 |

## 8. 成本回归测试

每次模型变更后，用固定评测集跑一遍，统计单任务平均 token 消耗，与基线对比。若成本涨幅超阈值（如 20%），触发告警并评估是否调整模型路由。

## 9. 测试环境与 CI/CD

| 环境 | 用途 |
| --- | --- |
| CI 流水线 | 单元 + 集成 + 沙箱安全（每次提交/PR） |
| Staging | E2E + 性能 + 成本回归（发布前） |
| Production | 冒烟测试 + 监控告警 |

CI/CD 集成：

- 单元/集成：GitHub Actions / GitLab CI
- 沙箱安全：独立 job，隔离网络运行攻击用例
- Agent 评测：定时任务（模型变更触发）

## 10. 验收标准汇总

| 类别 | 达标线 |
| --- | --- |
| 代码单元测试覆盖率 | ≥ 70% |
| 任务端到端成功率 | ≥ 70% |
| 代码可编译率 | ≥ 90% |
| 幻觉率 | < 5% |
| 沙箱逃逸 | 0 成功 |
| API P95 | < 200ms |
| 单任务成本 | 稳定在基线内 |
