# QA JSON 输入/输出映射内核（2026-11-08）

## 本轮范围

新增纯内核 `devpilot.qa_json_binding.QAJSONBinding`，是冻结评测计划的可执行映射前置能力，而不是完整计划服务。它能把一条 QA 的 `input` 写入已保存请求的指定 JSON 字符串字段，并从 JSON 响应的指定字段提取字符串。当前**尚未接入 UI/API、冻结计划持久化或 Worker**；已有组件测试不会自动改用它。

没有网络、模型、环境变量、数据库或文件访问；不接受 `expected`，不打分、不批准执行，不产生测试证据。准备好的完整请求仍包含秘密，只能在后续受认证执行边界内使用，不能写日志、发送给助手或作为公开 DTO。

## 映射契约

```json
{
  "schema": "qa-json-binding.v1",
  "input_pointer": "/messages/0/content",
  "output_pointer": "/choices/0/message/content"
}
```

- 路径是有界 JSON Pointer 风格，不是 JSONPath、Python 表达式或模板代码。支持 `~1` 表示 `/`，`~0` 表示 `~`；最多 16 段、512 UTF-8 字节。
- 输入必须映射到**已存在的字符串叶子**；不自动创建路径、追加数组、把对象或数字强转文本，也不允许替换整个请求根节点。数组索引不能是负数、前导零或 `-`；数字对象键仍按原字符串查找。
- 输出必须是字符串；空输出保留为空，不伪造结果。空 output pointer 可选根字符串。字段缺失、非文本、坏 JSON 都返回通用错误，后续执行器应记录技术失败，不能从有效分母中悄悄消失。
- QA 输入为非空白文本，最多 10,000 字符，原有空格不裁剪。它不读样本预期值，也不允许通过配置塞入金标答案。
- 完整请求先重新校验，然后复制：URL、方法、请求头（含顺序和重复头）不变，原对象不变。只替换一个正文叶子。JSON 空白/数字写法可能变化，但非目标值保持，使用 Decimal 保持原 JSON 小数精度。
- 严格拒绝重复 JSON key、NaN/Infinity、尾随内容、非法 UTF-8 文本；文档嵌套不超过 32 层，节点不超过 50,000。请求及映射后正文最多 256 KiB，响应文档最多 1 MiB，按 UTF-8 字节而非字符计算。
- `from_dict` 拒绝未知字段、缺失字段和未知 schema；配置是不可变 dataclass，render/extract 时重校验配置，错误不回显请求、路径或答案内容。

## 后续冻结计划应如何使用

1. 重新检查当前用户拥有项目、组件、请求版本与冻结 QA；比对 revision/hash 和请求密文摘要，不能信任客户端传来的快照。
2. 按人工确认的映射逐条预检，确保全部样本可形成合法、预算内的请求；保存映射 schema/路径，纳入不可变计划指纹。
3. 同时冻结 response mode、效果/性能参数、并发、超时、请求总量/预算和明确的人类执行确认。只有几个 ID 的库存记录不算可执行计划。
4. Worker 通过内部审计解密读取请求；执行前重验权限、版本完整性与出站策略，执行后先检查状态、截断和响应模式，再提取文本。保留失败项和原始逐条观测。
5. 金标由独立判定/复核边界读取，不送入被测组件。实际 A、预期、来源和技术错误进入人工复核视图，再关联版本化报告。

本内核仅处理 JSON 中的 QA 文本；不解码 SSE、计算 TTFT、处理图片/文件或替代 CV 标注协议。流式响应和 TTFT 必须由后续真实内容流适配器测量，缺失不能填零。JSON 提取成功本身不代表 HTTP 成功、输出合理或准确率达标。
