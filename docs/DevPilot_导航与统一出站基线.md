# DevPilot 导航与统一出站基线

日期：2026-11-07。该切片修复评测导航并统一组件请求的出站防线，不代表评测全流程已经完成。

## 1. 导航与助手的定位

- 评测页面只在主菜单保留一个“组件测试”入口；顶部不再重复同一链接。桌面、移动端保持一致，当前页有选中状态；移动端切页后自动收起抽屉，不再遮挡内容。
- 对话/助手页面仍保留“新建对话”，不删除已有会话或兼容路由。
- 原“智能体”是上游自定义对话助手的管理入口，不是已批准的效果/性能执行器，也不是报告助手的总开关。
- 改名为“自定义助手”：管理员启用 agents_api.enabled 时显示可操作链接，关闭/尚在发现状态时不显示置灰占位。不修改管理员开关、不扩大工具权限。
- 自定义助手可辅助需求梳理、方法解释、草稿说明；输出仍是建议，不能替代金标复核、真实测量、验收与报告批准。报告助手仍从报告模块按独立授权进入。

## 2. 统一出站路径

共同边界位于 app.evaluation.http：

1. cURL 调试通过 evaluation_client 和 PinnedEvaluationTransport 发送；保留原来的单次授权、响应大小和总超时限制。
2. 手动效果/性能启动增加 runs:create 权限；读取本人组件后先校验 RequestSpec URL/请求头及目标策略，拒绝时不创建运行、不排队。
3. 执行服务默认也使用同一客户端，避免仅入口检查后实际发送绕过策略。排队后发送时重新做 DNS 校验。
4. 定时评测不再维护独立传输实现，复用同一 PinnedEvaluationTransport；启动时仍检查计划指纹和权限。
5. 独立 toolkit 自建客户端改为开启 TLS 验证；独立工具并不因此自动拥有平台管理员白名单，调用方仍需提供批准的网络边界。

共同策略：精确主机白名单、HTTP(S) 且无 URL 内嵌账号、默认拒绝私网、即使批准私网也拒绝链路本地元数据等禁止地址、检查所有 DNS 结果、每次请求固定实际连接 IP、保留原 Host/SNI、拒绝改变 origin、不跟随重定向、不读取代理环境、不关闭 TLS 校验。RequestSpec 对用户请求头拒绝 Host/Content-Length 等危险覆盖和控制字符。

API 校验错误不回显提交值；组件接口响应使用 private, no-store。DNS/准入异常只返回通用错误，不能把原始异常里的地址或凭据返回给用户。

## 3. 使用与兼容性

在本地未提交的 config.yaml 中，由管理员配置 evaluation_http.allowed_hosts；需要内网目标时另行评估 allow_private。空白名单现在也阻止手动测试，而不仅是调试和定时路径。这是有意的安全收紧，不应通过关闭 TLS 或在前端绕过来恢复。

内部 HTTPS 自签证书需要管理员部署受信任 CA；没有增加“不验证证书”按钮。主机批准不是业务授权，发起者仍须确认接口调用、并发和费用已获授权。页面提示涵盖三个入口。

## 4. 未完成边界与下一阶段

本轮复用了 RequestSpec 的 URL/请求头校验和出站传输，但旧效果/性能协议仍构造各自的 body；尚未实现同一完整 RequestSpec 在调试、冻结提测、执行和导出之间无损贯通。

下一阶段仍需：凭据引用及请求版本、冻结可执行方案、耐久任务与取消/配额、逐条不可变观测和人工复核，再接平台证据报告。当前 inventory_only 提测清单不变，不能自动当作已批准执行计划。

本轮没有将手工报告、调试 HTTP 200、后台 completed 或缺测指标变成验收通过；没有调用真实客户接口或付费模型，也没有上传客户材料。

## 共享传输核心接续（2026-11-10）

既有 App 接口改为委托固定 `pinned-http.v1` 的实际传输机制，动态目的地策略和 ALL DNS answers 检查仍在 App；client 禁重定向、授权/预算/耐久派发/取消和未知结果不重发不变。新 callback 结果必须是 literal 无 scope IP，避免二次未经检查的 DNS。使用原 HTTPX，不新增依赖或执行/导出许可，旧 toolkit client 未切换。见[合同与验证](DevPilot_Shared_Pinned_HTTP_Core.md)。
