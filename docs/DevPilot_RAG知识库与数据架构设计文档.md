# DevPilot 知识库与数据架构设计 v3.0

> 2026-11-06；目标设计，尚未形成完整入库/审核/推广闭环。数据与分母规范见[数据集与指标](DevPilot_数据集与指标规范.md)。

## 1. 知识体系不是无限记忆

“不断学习”首版含义：**审核后的案例、材料、标注规则、适配器配置、Prompt/rubric 版本和回归集积累**，不等于自动训练模型，不等于把所有对话/报告直接喂给下一次验收。
知识推广需回归、审批与可回滚版本。DeerFlow 通用 memory 只辅助上下文，不是真实标签或权限管理的替代品。

## 2. 四类数据隔离

| 区域 | 用途 | 可访问者 / 限制 |
| --- | --- | --- |
| 项目原始区 | cURL 原件、样例、文档、图像、历史结果 | 最小项目授权，扫描/脱敏；凭据独立存 |
| 工作知识区 | 授权源、标签规则、开发样例、候选难例 | 助手可检索指定 scope，不含冻结盲测答案 |
| 验收隔离区 | 冻结 acceptance 数据与预期 | 执行器只取输入；裁判/审核者按需取预期；目标和普通助手不直取答案 |
| 发布经验区 | 脱敏归纳、模板、通用规则/adapter | 审核后按 scope 检索；跨项目共享须另行授权 |

同一原件可派生多个版本，但用途许可不同；参考来源与 reference answer 分开。检索权限在候选召回前过滤、结果返回前复验，不能先把无权数据发给 reranker/LLM 再隐藏 UI。

## 3. 历史材料导入流程

清单登记 → 权限/许可证确认 → 恶意文件/压缩包限额扫描 → 解析 → 敏感项/凭据检测 → 结构化项目与来源映射 → 候选知识 → 人工审查 → 版本发布 → 索引。
支持格式逐项实现与声明；扫描件 OCR/表格解析需质量提示和人工核对，解析成功不等于标签可信。原始 cURL/日志可能带 key/个人数据，先隔离再清洗。

每个知识项保存 source_refs/hash、授权用途、项目/owner、敏感级别、有效时间、知识类型、reviewer、修订、适用组件/任务、禁用范围、回归证据和撤销理由。

## 4. 检索最小方案

先按组件类型/任务/标签/来源/项目做结构化过滤，配全文检索；试点确认语义召回缺口后，再加 embedding、向量检索和 reranker。SQLite 可用于本地；PostgreSQL + 可选 pgvector 可支持多人，Milvus 仅在规模/运维需求证实后选用。
Embedding 模型和索引版本冻结，记录 chunk 到原文页/段/图的映射。长文按章节/业务语义切分，不能截断表格/标签；保留原文引用，不靠模型回忆出处。

## 5. 防污染与持续优化

- 来源快照与 split 按主体/时间/文档隔离，阻止 acceptance 泄漏到生成和校准。
- 运行失败记录进入候选池，不自动改当前数据；复核后创建下版回归集。
- 从整改提炼“适用条件 + 证据 + 反例”，不保存“上次 PASS 所以下次应 PASS”。
- 经验/Prompt 推广先离线重放校准和回归，再审批小范围启用；效果变差可回滚索引/Prompt/规则版本。
- 检测来源中的提示注入，工具不执行文档指令；索引不含明文凭据。
- 人员或项目权限撤销后，同时撤销索引、缓存和下载权限。

## 6. 质量衡量与删除

检索测授权范围内 Recall@k/引用可定位率/无答案误引；知识测复用有效率、误导率、过期率、人工纠错和跨项目泄漏。以独立查询集验证，不用训练/验收答案自证。
保留期限、敏感数据是否允许外部 embedding/裁判，必须由组织 policy 确认。删除覆盖原件、派生 chunk/embedding、缓存和访问许可，记录合法审计 tombstone 与备份过渡风险，不声称删除 DB 行即完全遗忘。

## 7. 复核反馈不直接等于知识发布

ReviewDecision 的理由/难例可脱敏形成 KnowledgeCandidate，仍需授权、来源检查和独立审核；一次人工 PASS 不是通用规则，也不能自动改当前 rubric/Prompt。金标纠错先生成新数据版本，再评估对基准/历史报告的影响。
接口调试响应、导出包内答案、复核画面和仲裁证据不默认进入聊天记忆/公共 RAG；按 subject/hash 保留受限引用。导出只授予明确的数据范围，受限验收资料仍与可检索经验隔离。
