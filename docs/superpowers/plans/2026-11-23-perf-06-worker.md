# PERF-06 Synthetic Performance Worker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consume an explicitly admitted frozen performance run through the existing durable lease/fence ledger using only a synthetic in-process transport, and account for every frozen ordinal without enabling real target traffic.

**Architecture:** Add an App-owned worker service invoked only explicitly by tests/internal callers, with injected bounded request source and a synthetic transport implementation; do not register an automatic startup loop or public run endpoint. The worker must perform claim ? ACK ? fenced start ? synthetic response ? observation, preserve unknown/no-resend semantics on uncertain outcomes, close the measurement window only after all ordinals are accounted for, and rely on the existing encrypted response artifact flow. Reject non-synthetic transports at this stage.

**Tech Stack:** Python 3.12, FastAPI App domain conventions, SQLAlchemy async repositories, pytest/pytest-asyncio, SQLite isolated tests; PostgreSQL remains the production database and required migration/integration parity gate.

**Spec:** `docs/DevPilot_AI?????????.md` (PERF-04/05 and execution safety sections), `docs/DevPilot_Admitted_QA_Execution.md`, and `docs/DevPilot_Execution_Safety_Contract.md`.

## Global Constraints

- PostgreSQL is the default persistent backend; SQLite is test-only isolation and never a production fallback.
- No real model, target, network, automatic scheduling, retry, resend, or production deployment.
- Only explicitly admitted runs may be consumed; retain owner/project/run scoping and current worker/epoch/lease fences.
- Unknown write/delivery outcomes are read-only reconciled by the original IDs; never create a replacement dispatch or infer worker death from a deadline.
- Preserve frozen population, measured denominator, warmup distinction, request/response byte budgets, request timeout, wall deadline, duration limit, and drain bound.
- Persist one observation/evidence status for every ordinal; missing or uncertain observations are never PASS.
- No new dependency unless separately justified; do not expose transport execution through public APIs in this slice.
