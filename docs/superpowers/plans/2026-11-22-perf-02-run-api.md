# PERF-02 Run Ledger API Implementation Plan

**Goal:** Expose the existing durable performance run ledger through authenticated, owner-scoped APIs without starting target traffic.

**Architecture:** Add a strict run-creation request bound to an immutable scenario hash and explicit confirmation. The client preallocates a 32-character lowercase hex run ID and persists it before POST so unknown writes can be reconciled by GET on the same ID without resubmission. Provide run summary and paginated dispatch reads through the existing performance router. The API never invokes a transport or worker. Outbound admission, authorization, artifact receipt binding, and worker scheduling remain separate follow-up slices.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy async, pytest.

**Spec:** `docs/DevPilot_AI性能测试工作台设计.md`, sections 4-6 and 9; existing PERF-02 ledger contract.

## Constraints

- PostgreSQL remains the production database; use isolated test databases only.
- Require authenticated human identity and evaluation project permissions.
- Bind every operation to owner, project, run, and scenario as applicable.
- Require `confirmed: true` and the exact immutable scenario definition hash to create a run.
- Require a client-preallocated `run_id`; on an unknown POST result, perform GET-only reconciliation with that ID. Never retry POST or create a replacement ID automatically.
- Never dispatch requests, enqueue background work, or imply that run creation starts execution.
- Bound pagination and preserve stable 404/409/422/503 API behavior.
- Do not expose sensitive request/response bodies or credentials.

## Tasks

### 1. API contract tests

- Add failing tests for run creation confirmation, scenario hash mismatch, ownership, run summary reads, dispatch pagination bounds, and absence of target/network side effects.
- Confirm the tests fail because run endpoints do not exist.

### 2. Routes and DTO

- Add a strict request DTO containing `run_id`, `scenario_id`, `scenario_hash`, and `confirmed`.
- Add `POST .../performance-runs`, `GET .../performance-runs/{run_id}`, and bounded `GET .../performance-runs/{run_id}/dispatches` routes.
- Reuse the existing permission, human identity, private response, and repository error mapping patterns.
- Keep run creation ledger-only; no worker hook or background task.

### 3. Documentation and verification

- Update the API contract and progress ledger to distinguish run-ledger reads/writes from admission and execution.
- Run focused router/repository tests, Ruff, formatting, and `git diff --check`.
- Run the required backend test gates before any commit or push; record exact SHA and Actions before merging to `main`.
