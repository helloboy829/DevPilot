# PERF-02 Durable Performance Ledger Implementation Plan

**Goal:** Add an owner-scoped immutable performance-run ledger and deterministic metrics bound to PERF-01 scenarios, without enabling outbound traffic.

**Architecture:** Create performance-specific run, dispatch, and audit tables because the existing dispatch journal is effectiveness-only. Freeze the scenario manifest as the full ordinal population. Require a durable send acknowledgement before any future network I/O and persist a single terminal observation per ordinal. Pure versioned metrics use only measurement-window dispatches.

**Tech Stack:** Python 3.12, SQLAlchemy async, Alembic, Pydantic, SQLite migration tests, PostgreSQL-first persistence.

**Spec:** Performance workbench design, sections 3-6 and PERF-02 acceptance row.

## Global Constraints
- PostgreSQL is the production database; migrations are additive and downgradeable.
- No real target request, deployment, or automatic retry is enabled by this slice.
- Existing effectiveness dispatch journal behavior remains unchanged.
- Duplicate case IDs remain separate manifest ordinals.
- Ambiguous writes/results are reconciled read-only with the same ID; never resend.
- Evidence bodies use shared EVID-02 storage; this slice stores bounded metadata/hash references only.
- Synthetic/local tests only; PostgreSQL live parity requires an already approved exclusive test database.

### Task 3: Owner-scoped repository
Files: create backend/app/evaluation/performance_run_repository.py; test backend/tests/test_performance_run_repository.py.
Interfaces: create_run(owner, project_id, scenario_id, expected_scenario_hash, confirmed) validates owner, hash, manifest and confirmation, then atomically writes the run, all ordinal rows and audit; grants no network authority. acknowledge_dispatch(...) permits one pending-to-dispatched transition after bounds/window checks and returns a stable ticket after commit. record_observation(...) records one bounded terminal outcome exactly once. interrupt_run(...) marks dispatched work unknown and undispatched work not_dispatched. Reads are owner-scoped, pagination-bounded and reconcile summary counts against persisted rows.
