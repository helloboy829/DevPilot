# DevPilot 冻结 QA 计划确认界面

更新：2026-11-08。仅创建与浏览冻结定义，不是启动、运行或验收界面。

## 使用流程

1. 在“项目与数据”选择本人项目；在项目清单关联需要评测的组件。
2. 在接口调试器粘贴 cURL、解析和编辑；如需保存完整请求版本，另行明确确认加密存储。接口发送确认与存储确认互不替代。
3. 导入 QA、核对 Q/预期/来源，并明确冻结数据集。
4. 回到“项目与数据”底部“冻结 QA 评测计划”，点击加载来源、选择组件。读取该组件的请求版本元数据、计划元数据及同项目冻结数据元数据，不读取金标或完整请求。
5. 选择两个版本、填写新计划名及输入/输出 JSON 指针。输入指针必须指向现有字符串叶子；不自动猜测或建立字段，保留路径空格。输出空指针仅通过“响应根节点本身是 JSON 字符串”显式启用。
6. 配置效果/性能模式及未来运行参数。效果请求数由全量样本数确定，性能请求数需至少覆盖全部样本，按样本 ID 升序循环；均不能将冻结当作效果通过。超时、总时限、并发及正文预算按服务端契约严格校验。
7. 核对请求摘要、QA revision/hash/用途，勾选“仅冻结定义”确认；冻结会在服务端内部审计解密并逐 Q 预检，但不调用目标接口。预检不证明输出路径实际存在。
8. 已保存版本可展开查看固定设置、预检样本/请求数量及正文字节、hash、顺序和人工复核策略。任何修改都需创建新版本，界面不覆盖旧计划。

## 交互和边界

- 普通登录用户沿用自身 read/write/review 权限；不提高权限、不关闭 owner 隔离。工作模型不是创建计划的前提；保存/预检需要运维独立请求加密密钥，缺失按服务端 503 拒绝，界面不生成或展示密钥。
- 表单与元数据仅放页面内存，不进 URL、聊天、localStorage、sessionStorage 或持久查询缓存。刷新页面需重新加载来源。标签和字段路径仍可能有业务语义，不称匿名数据。
- 任何字段/版本/组件修改、来源刷新、失败或提交都会撤销确认。正在处理时控件禁用，并用同步 ref 锁阻止重复提交。
- 任何未确认成功的写入（包括网络中断）保留编辑内容，但禁止直接重试。需明确刷新版本与已有计划，先核对是否已写入；没有自动重试或伪造成功。
- 按项目 key 重挂载与生命周期 token 丢弃旧项目迟到响应。相邻清单/计划使用不同 key 前缀，避免项目切换时重复挂载控件。切组件立即清空原请求/数据选择与计划，避免跨范围展示和提交。
- 中英文、移动端、light/dark 及既有工作区主题沿用语义颜色；表单具有可访问名称。QA 计划没有流式能力，不显示 TTFT 或推测 token 吞吐。

## 验证

先运行缺失 plan-form 模块的单测红灯，再在旧构建独立端口运行“计划入口缺失”浏览器红灯，之后实现。长期驻留的 3000 测试服务曾停留在过期构建状态，已改用独立端口的临时生产构建服务，不通过强制点击绕过禁用。

参数契约测试覆盖完整效果覆盖、性能循环、严格整数/范围、指针字节/深度/转义、保留路径空格、根字符串显式选择、版本 scope/hash 和人工确认；浏览器回归覆盖实际 DTO、无目标调用/金标读取/缓存、确认失效、组件切换、409/503/网络未知写入恢复、迟到响应和中文小屏。完整回归曾发现清单和计划相邻组件使用相同 key，导致清单控件重复；已改为独立 key 命名空间，保留原清单断言并新增多次切换项目的回归。

最终隔离验证：前端 **135 文件 / 1,049 单测通过**，完整普通浏览器 **187 通过**、独立认证恢复 **2 通过**；eslint、TypeScript、全前端 Prettier 与生产构建通过。测试使用合成数据与 API mock，不证明真实组件可运行。

本地 gateway/frontend 已替换并只读验烟：在线备份完整性通过，原账号完整行、旧评测行、配置哈希、原挂载、两个迁移账本和无关服务保留；518 个前端源文件 hash 一致。所有现有账号的助手入口、手动配置、五主题、请求元数据与计划只读入口通过，未调用模型、创建助手或写入业务数据。仍未配置模型及独立请求加密密钥，不擅自生成；没有声称真实计划创建/模型连通验收。GitHub CI 须按实际推送完整 SHA 另行核对，不将本地通过视为远端通过。

## 下一步

独立执行准入（目标授权、重新确认、响应/流量预算、禁止不确定重发）→ 耐久 Worker 与不可变逐条观测 → 人工复核 → 版本化报告证据。不能把冻结 API 的内部解密函数直接当作执行授权；本切片没有执行按钮、执行 API、调度接入、自动裁判或报告事实连接。
