# DevPilot 基于 DeerFlow 的改造方案 v3.0

> 2026-11-06。旧研发专用 Skills / 七字段评分 / M1–M5 完成叙述不再作为当前产品验收依据。

## 1. 改造原则

复用通用底座，新增评测领域，不把 DeerFlow 整体重写为另一套 runtime。产品核心由聊天转为评测项目；自动化受业务审批与预算约束。

## 2. 保留、隐藏、禁用、删除矩阵

| 能力 | 首版决策 | 原因 / 条件 |
| --- | --- | --- |
| Gateway、认证/owner、SQL/Alembic、artifact、日志 | 保留并复用 | 安全和持久化基础；不可为轻量直接裁掉 |
| LangGraph、模型工厂、Skill/Tool、扩展契约 | 保留 | 规划、候选生成、检索和报告助手 |
| 沙箱 | 按需保留，优先隔离模式 | 数据转换/可信脚本需要；普通 HTTP 评测无需执行任意 shell |
| Chat/通用 Agent 页面 | 从主导航移出，保留兼容路由 | 调试助手和历史会话仍有价值 |
| 博客、landing、showcase、语音 | 评测入口隐藏，后续评估可删 | 非业务主线；先确认路由/构建依赖 |
| IM、集成、定时任务、远程 MCP | 默认不启用，按需求授权 | 整改通知/定时回归后续选择性启用 |
| 自动记忆、自由修改 Skill | 对评测知识受控，不直接充当知识库 | 验收答案隔离、审核和回滚要求 |
| 旧七字段代码评分 | legacy 命名与兼容，不做通用主契约 | taskScore/codeScore 不适合 CV/QA |
| 向量数据库 | 需求验证后可选 | 结构化检索起步，避免空转基础设施 |

**隐藏不是卸载；禁用不代表已有统一开关。** 目标是后端 capabilities 与导航一致；不存在的开关需要实现/测试，不能只写配置就宣称安全关闭。

## 3. 代码落点与改造顺序

1. 先修 toolkit/服务/API 的可信度、安全、Docker 和恢复缺陷，见[审计](DevPilot_现状审计与修复清单.md)。
2. 新业务应用服务置 backend/app，纯领域逻辑置 devpilot/src/devpilot，模型能力经依赖注入。
3. 在 frontend 新建 evaluation 域和项目中心，复用认证、TanStack Query、UI 基元，不复制聊天 stream 当业务状态。
4. 评测工具按最小权限暴露给 Lead Agent：检查提测、提议方案、生成候选、请求审批、提交已批准运行、读证据和草稿报告。
5. 经历史项目试点后再做裁剪，保留一段兼容期和受支持配置矩阵。

plugins 使用 config.yaml 的 operator-only 列表，当前 schema 为 use: package.module:install + config，不是旧文档的 module:；不能经 API-writable extensions_config.json 导入任意 Python 代码。
产品核心业务不应依赖 gitignored 的 skills/custom。若交付自定义技能，选择受版本管理的目录并完成发现/打包/测试；本仓库未追踪的五个旧研发技能不得再列为已交付。

## 4. 裁剪前置检查表

- 依赖图：Python import、路由/lifespan、配置、权限、前端引用、环境变量、镜像与测试。
- 分别测试隐藏与禁用；直达 URL/API 不可绕过禁用能力。
- 评测 profile 必须测试鉴权、artifact、LangGraph 和旧链接。
- 每次删除只处理一类功能，记录 upstream commit/base、变更补丁和升级冲突。
- 镜像体积/依赖/启动收益先测量再决定，不以删文件数论成效。
- 数据表/迁移不随页面隐藏删除；物理清理需备份、保留策略和单独审批。

## 5. 前端调整

主入口改为项目总览；一级导航为项目、提测组件、接口调试、数据集、评测运行、人工复核、报告/整改、知识库、设置；空间不足时将调试折叠在组件内，但保留明确入口。项目内逐步引导：材料→调试/接入确认→数据→方案→平台执行/可选导出→人工复核→报告/复测。
助手以项目上下文侧栏存在，不要求用户会 Prompt、Python 或 JSON。详细交互见[前端设计](DevPilot_前端交互设计.md)。

## 6. 验收标准

同一项目在 UI/Agent/API 上执行得到相同业务门禁；关闭的入口不能直连绕过；旧数据可读；评测镜像可独立 import devpilot；任何裁剪都不削弱权限或证据完整性。

## 7. 新增范围与裁剪纪律

新增领域服务是 RequestSpec 调试/确认、可选独立 Python 工程导出、ReviewTask/Decision/Resolution 和 assessment 重算；复用现有 Gateway、权限、Job/事件与 UI 基元，不修改 DeerFlow 底座去承载专用评测业务。Agent 不自由写未审核脚本，也不拥有人工裁决能力。

本轮只清理用户明确不需要的日/法/俄 README 并修复引用；中英文文档保留。运行时 UI locale、IM/沙箱/工具模块及其数据没有因此删除。其他裁剪仍按依赖、关闭入口和回归矩阵另行实施。
