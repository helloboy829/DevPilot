# 请求版本操作闭环（2026-11-08）

## 本轮交付

组件测试页的 cURL 调试器新增「保存请求版本」与「查看请求版本」。前者使用当前编辑器的 URL、方法、请求头和请求体快照；后者无需导入 cURL 就能查看本人项目/组件下的元数据。所有已登录用户均可进入已有助手库；助手保存配置无需调用模型，真实对话仍依赖可用模型。

### 使用步骤

1. 在组件测试页粘贴完整 cURL，解析后检查/编辑请求。
2. 如需验证接口，单独确认并发送。**保存请求不会触发发送，也不证明接口已调通。**
3. 点击「保存请求版本」，显式加载项目，选择已关联的项目组件。尚无项目/组件时可前往 QA 数据页创建/关联。
4. 填写不含敏感信息的版本标签，确认将完整请求（可能含凭据）加密保存到所选组件，再提交。
5. 返回的元数据包含版本 ID、时间、origin、方法、头名称、结构指纹及密文摘要。既无请求值也无密文下载；摘要不是签名。
6. 不确定写入是否成功时先「加载已保存版本」核对，不自动重试。重复标签由服务端拒绝；这是只追加版本，不支持覆盖。

## 安全与交互边界

- 沿用 authenticated / CSRF / no-store 的 evaluationApi；服务器继续执行 read / write + review 权限和 owner 隔离，不因 UI 可见而绕过权限。
- 当前请求仅保留在页面内存；弹窗不二次渲染完整 URL、头值或请求体，不使用浏览器持久存储、对话或持久 query cache。元数据 origin/头名称仍可能有业务含义，不是匿名化产物。
- 项目、组件、标签变化与操作失败都撤销保存确认；保存中锁定字段、重复提交和关闭。返回编辑器再打开保存时需要重新确认。
- 显式加载列表；项目切换清除旧组件、标签、成功提示和历史，防止错项目保存。异步完成不更新已卸载弹窗。
- 请求头必须为名称/值二维字符串数组，服务端继续严格校验完整请求。错误展示通用说明，不回显输入或服务端内部异常。
- 保存失败保留编辑内容；成功不会销毁原请求，便于继续调试。离开页面或「清除凭据与内容」会清除编辑器请求。
- 中英文、键盘 Escape、移动端宽度均有回归覆盖。调试发送同意与加密存储同意彼此独立。

## 密钥与部署

保存 API 仍要求运维显式提供独立的 `DEVPILOT_REQUEST_ENCRYPTION_KEY`。缺失时按设计拒绝保存；元数据读取不要求密钥。前端新增功能不会生成/修改密钥、已有模型设置、账号或数据卷。不要将真实请求、配置、密钥或备份提交至 Git。

本轮没有新增迁移，App head 保持 eval_0003；后端加密存储 API 未改变。更新本地服务时先在线备份并校验完整性，再只重建 gateway/frontend，刷新 nginx；确认原账号、评测行、配置哈希、挂载和迁移 ledger 保留，不触碰其他服务。

## 尚未完成

这次交付是请求定义的实际 UI 闭环，不是冻结评测计划。请求版本尚未绑定 QA 样本映射、冻结 revision/hash、效果/性能参数、执行批准或耐久 Worker；没有公开解密/重放入口、可复用凭据仓库或换钥工作流。后续顺序：冻结计划契约与显式确认 → 耐久执行及逐条观测 → 人工复核 → 证据绑定报告。TTFT 仅用于实测内容流，缺失不能填零。
