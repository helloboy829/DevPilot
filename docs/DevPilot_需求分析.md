# DevPilot 需求分析 v3.0

> 2026-11-06；目标需求，当前仅覆盖小部分，见[现状审计](DevPilot_现状审计与修复清单.md)。

## 1. 角色

- 提测方：组件/版本、接口、样例、参考来源、授权与整改证据。
- 评测工程师：接入、数据/负载方案、执行和异常处理。
- 领域复核人：标签、答案、容差和争议审核。
- 报告审批人：验收证据、风险与发布。
- 管理员：目的地策略、凭据、配额和部署能力。

首版可由同一人承担多角色，但每次审批仍记录 actor、版本、时间和意见，不允许 Agent 自批。

## 2. 领域对象

Project 管理评测项目；Submission 保存提交材料；Component/ComponentVersion 描述被测对象；EndpointRevision 保存 RequestSpec 和提取器，EndpointCheck/Confirmation 保存调试证据与确认；SourceDocument 保存合法来源；Dataset/DatasetVersion 管理数据；EvaluationPlan 审批冻结；EvaluationRun 执行；CaseResult/Judgment/Metric 保存证据，ReviewTask/Decision/Resolution 与 RunAssessmentRevision 保存人工裁决和重算，ScriptExport/ExternalResultImport 管理独立工程与外部证据；Report/Remediation/Retest 管理闭环；KnowledgeEntry 沉淀审核经验。
版本、接口或数据变化需新版本，不覆盖旧运行依赖。

## 4. 业务规则

1. 冻结组件版本、请求模板、数据、指标阈值、裁判和环境指纹。
2. 修改审批对象使审批失效；执行生成不可变快照。
3. Agent 可提出计划和标签，无权绕过数据、负载、报告审批。
4. 网络错误、待复核、未执行分别计数，不当作语义错，也不移出分母。
5. 效果/性能独立执行，不混用负载；按任务判定指标适用性。
6. 缺必需指标、零样本、授权不明不得 PASS。
7. “合理即可”须转成可审核语义维度/容差，不等于文本模糊匹配。
8. 报告标明样本范围与局限，试点不等于通用排行榜。
9. 单次接入成功不授予压测许可；接口修订/环境/提取器变化须重新确认。
10. 人工决定不覆盖自动裁判和原始响应，ERROR/NOT_RUN 不可人工改 PASS；重算保留总分母。
11. 导出权限与查看权限分离；外部执行结果隔离校验，不自动成为可信正式验收。

## 5. 非功能

凭据独立引用、加密与 DTO 脱敏；内网采用管理员批准策略，防 SSRF/重定向/本地文件读取；项目、数据、运行和 artifact 全链隔离，无团队权限模型前不共享。
所有任务限制并发、次数、时长、体积和费用；压测需窗口与紧急停止。DB 是业务真相源，原始观测可离线重算，不以重算重新访问目标。平台吞吐/RTO/RPO 通过试点后设定，不凭空承诺 SLA。

## 6. MVP 完成定义

不写 Python 即可完成一个真实问答组件的提测、接入、授权数据导入、复核、冻结、效果/性能、失败定位、基础报告和同配置复测。Agent 不暗改标准。CV 独立验收，不以 HTTP 返回 JSON 宣称覆盖所有 CV。
