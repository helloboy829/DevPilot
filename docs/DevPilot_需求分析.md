# DevPilot 需求分析文档 v1.0

## 0. 文档说明

**目的**：定义 DevPilot 的产品需求，明确功能范围、优先级、用户场景与非功能约束，作为概要设计与详细设计的输入。

**前置结论**（源自《可行性分析》）：

- 目标用户：个人开发者 / 小团队
- 部署形态：SaaS 云服务
- LLM 策略：国产模型为主 + 多模型路由
- 协作深度：仅个人空间（首版不做共享项目与成员权限）
- 执行引擎：双模式（流水线 + 自由循环）

## 1. 产品定位

面向个人开发者与小团队的 SaaS 多智能体研发协同平台。用户输入自然语言需求，平台自动完成「需求分析 → 设计 → 编码 → 测试 → 评估 → 报告」的完整研发闭环，并以 Agent 自由循环模式支持 Bug 修复、代码审查、脚本生成等任务。

## 2. 目标用户与用户故事

### 2.1 用户画像

| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| 独立开发者 | 单人全栈，时间有限 | 快速生成可用代码，减少重复劳动 |
| 小团队工程师 | 3-10 人，职责杂 | 自动化测试与质量评估，提升交付效率 |
| 学生/学习者 | 预算有限 | 低成本体验 AI 辅助开发 |

### 2.2 核心用户故事

1. 作为独立开发者，我想输入「做一个订单管理系统的后端」，系统能生成可运行的项目代码，我就能直接在此基础上继续开发。
2. 作为工程师，我想输入「修复这个仓库登录模块的报错」，系统能定位问题并给出可编译的修复。
3. 作为工程师，我想对一段代码做审查，系统能给出质量评分与改进建议。
4. 作为学习者，我想写一个爬虫脚本，系统能生成脚本并运行给我看结果。
5. 作为用户，我想在系统执行高风险操作前确认，避免误删或误提交。

## 3. 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 任务（Task） | 一次完整的研发请求，是执行与计费的基本单位 |
| 流水线模式（Pipeline） | 固定 9 节点顺序执行，适合从零生成项目 |
| 自由循环模式（Agentic Loop） | 单 Agent + 工具集 + 沙箱的 ReAct 自治循环，适合修复/审查/脚本 |
| 工作空间（Workspace） | 任务的隔离文件环境，Agent 在其中读写代码 |
| 沙箱（Sandbox） | 隔离的执行容器，Agent 在其中运行代码/命令 |
| 审批（Approval） | 关键/高危操作前暂停，等待用户确认的机制 |
| 评测（Evaluation） | 对任务结果的质量评分（7 字段） |
| Trace | 任务执行的全链路记录（节点、token、耗时、状态） |
| 信用点（Credit） | 计费单位，一次任务消耗若干信用点 |

## 4. 用例模型

### 4.1 主要用例图（文本）

```
用户
├── 注册/登录
├── 创建项目（个人）
├── 创建任务（含目标、任务类型）
├── 启动/停止/恢复任务
├── 查看实时执行过程（SSE）
├── 审批关键操作
├── 浏览/编辑/下载生成文件
├── 查看 Trace
├── 查看评测报告
├── 管理个人知识库（P1）
└── 查看用量与账单
```

### 4.2 核心用例流程

**用例 UC-01：创建并执行「从零生成项目」任务**

```
主流程：
1. 用户输入任务标题 + 目标描述 + 选择任务类型「全栈生成」
2. 系统创建任务（status=CREATED），创建隔离工作空间
3. 用户启动任务 → Manager 路由到流水线模式
4. 流水线依次执行 Planner→Research→Architect→Coding→Execution→Testing→Evaluation→Report
5. 执行中通过 SSE 实时推送节点状态
6. 关键/高危操作（提交、执行外部命令等）弹出审批，用户确认后继续
7. 任务完成，用户查看生成文件与评测报告

异常流程：
- 测试失败 → 进入自修复循环（Testing→Coding→Execution），超过最大迭代次数则终止并报告
- 节点超时/LLM 异常 → 重试/降级模型，仍失败则保存 Checkpoint，支持恢复
```

**用例 UC-02：修复 Bug（自由循环模式）**

```
主流程：
1. 用户上传/选择已有仓库，输入「修复 XX 报错」
2. Manager 路由到自由循环模式
3. Agent 在沙箱中反复：读文件 → 定位 → 修改 → 运行测试 → 观察报错 → 再修改
4. 关键操作审批
5. 产出可编译的修复 + 变更说明
```

## 5. 功能需求

优先级定义：**P0 = MVP 必须**；**P1 = MVP 后第一迭代**；**P2 = 远期**。

### 5.1 账号与认证（P0）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-AUTH-01 | 用户注册/登录 | 邮箱 + 密码，JWT 认证 |
| FR-AUTH-02 | 个人空间隔离 | 每个用户独立工作空间，数据互不可见 |
| FR-AUTH-03 | 密码找回 | 邮箱验证码 |

### 5.2 项目管理（P0，仅个人）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-PROJ-01 | 创建项目 | 用户私有项目，作为任务的归属容器 |
| FR-PROJ-02 | 项目列表/删除 | 删除需二次确认 |

### 5.3 任务管理（P0）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-TASK-01 | 创建任务 | 输入标题、目标描述、任务类型（全栈生成/脚本生成/代码审查/Bug 修复） |
| FR-TASK-02 | 启动/停止/恢复任务 | 支持取消进行中的任务；失败/中断后可恢复 |
| FR-TASK-03 | 任务状态机 | CREATED → RUNNING → PAUSED(审批) / SUCCESS / FAILED / CANCELLED |
| FR-TASK-04 | 历史任务列表 | 按项目/时间筛选，查看历史结果 |

### 5.4 Agent 执行引擎（P0，双模式）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-EXEC-01 | 路由分发 | Manager 依据任务类型路由到流水线或自由循环 |
| FR-EXEC-02 | 流水线模式 | 9 节点：Manager→Planner→Research→Architect→Coding→Execution→Testing→Evaluation→Report |
| FR-EXEC-03 | 自由循环模式 | 单 Agent ReAct 循环：think→act→observe，工具集 + 沙箱 |
| FR-EXEC-04 | 自修复循环 | 测试失败回退到 Coding，设最大迭代次数上限（默认 3） |
| FR-EXEC-05 | 工具集 | 文件读写、Shell 执行、Git、代码搜索、RAG 检索（P1） |
| FR-EXEC-06 | SSE 实时流 | 推送节点状态、Agent 消息、工具调用状态 |
| FR-EXEC-07 | 异常恢复 | 节点失败重试、LLM 降级模型、Checkpoint 恢复 |

### 5.5 Human-in-the-loop 审批（P0，关键节点）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-HITL-01 | 审批触发点 | 提交代码、执行外部命令、修改数据库、删除文件等高危/关键操作 |
| FR-HITL-02 | 审批交互 | 任务 PAUSED，SSE 推送审批请求，用户「同意/拒绝」后继续 |
| FR-HITL-03 | 审批超时 | 超时（如 30 分钟）默认拒绝并终止 |

### 5.6 工作空间与文件（P0）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-WS-01 | 文件浏览 | 树形展示生成文件 |
| FR-WS-02 | 文件内容查看/编辑 | 在线预览，支持编辑 |
| FR-WS-03 | 文件下载 | 打包下载整个项目 |

### 5.7 评测与报告（P0）

| --- | --- | --- |
| FR-EVAL-01 | 7 字段评测 | taskScore / codeScore / testScore / hallucinationRate / confidence / overall / report |
| FR-EVAL-02 | 评测报告展示 | 前端可视化展示评测结果 |

### 5.8 Trace 追踪（P0）

| 编号 | 需求 | 说明 |

| FR-TRACE-01 | 执行链路记录 | 节点名称、输入、输出、token 消耗、耗时、状态 |
| FR-TRACE-02 | Trace 查看 | 前端可视化展示执行链路 |

## 6. 非功能需求

### 6.1 性能

| 编号 | 指标 | 目标 |
| --- | --- | --- |
| NFR-PERF-01 | SSE 首字节延迟 | < 500ms |
| NFR-PERF-02 | 沙箱创建 | < 5s |
| NFR-PERF-03 | 任务响应 | 简单脚本任务 < 60s 完成 |
| NFR-PERF-04 | 并发 | 支持 100 并发任务（MVP 阶段） |

### 6.2 安全

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-SEC-01 | 沙箱隔离 | 网络隔离、资源限额、超时、只读文件系统、逃逸防护 |
| NFR-SEC-02 | 认证 | JWT + 密码加密存储（bcrypt） |
| NFR-SEC-03 | 接口防护 | API Rate Limit、输入校验 |
| NFR-SEC-04 | 数据加密 | 敏感数据加密存储，传输 TLS |
| NFR-SEC-05 | 多租户隔离 | 任务/文件/知识库严格按用户隔离 |

### 6.3 可用性

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-AVAIL-01 | 服务可用性 | ≥ 99.5% |
| NFR-AVAIL-02 | 任务可恢复 | 中断/失败后可从 Checkpoint 恢复 |

### 6.4 可维护性

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-MAINT-01 | LLM 接口抽象 | 可无痛切换/接入不同模型供应商 |
| NFR-MAINT-02 | 可观测性 | 结构化日志 + 指标监控 + Trace 持久化 |
| NFR-MAINT-03 | 配置化 | 模型、token 上限、迭代次数等可配置 |

### 6.5 合规

- 国产模型为主，数据境内处理
- 隐私政策 + 用户数据删除能力
- 生成代码版权免责条款

## 7. MVP 范围定义（P0）

MVP 交付的最小闭环：

1. 账号注册/登录，个人空间隔离
2. 创建任务（4 种任务类型），双模式执行引擎
3. 沙箱隔离执行 + 工具集（文件/Shell/Git）
4. SSE 实时流 + Trace 查看
5. 关键节点审批
6. 生成文件浏览/下载
7. 7 字段评测与报告
8. 模型路由 + token 上限 + 用量记录

**MVP 明确不做**：共享项目/成员权限、团队知识库、计费系统（先用固定套餐）、RAG（P1）。

## 8. 迭代路线图

| 阶段 | 内容 | 目标 |
| --- | --- | --- |
| **M0 PoC** | 沙箱安全验证 + 最小自由循环跑通 + 成本实测 | 验证技术可行性与成本 |
| **M1 MVP** | 双模式引擎 + 账号 + 沙箱 + SSE + 审批 + 评测 | 单人完整闭环可用 |
| **M2 增强** | RAG 知识库 + 计费系统 + 模型路由优化 | 知识增强 + 商业化 |
| **M3 协作** | 共享项目 + 成员权限 + 团队知识库 | 兑现小团队定位 |
| **M4 扩展** | Agent Benchmark、企业权限、私有化 | 规模化与商业化 |
