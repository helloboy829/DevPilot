# DevPilot 业务流程与迭代计划

> 2026-11-06；目标流程。所有阶段均待对应代码和验收证据，不继承旧 M1–M5 完成状态。

## 1. 业务阶段与交付件

| 阶段 | 输入 | 自动化 | 人工门禁 / 输出 |
| --- | --- | --- | --- |
| 提测 | 清单、cURL、样例、来源 | 解析/缺项提示/凭据分离 | 提测方确认；Submission/组件版本 |
| 接入 | cURL / RequestSpec 和批准目标 | 人/Agent 共用调试，协议/提取/首内容验证 | 工程师确认指定修订/环境；单次脱敏证据，不授予压测许可 |
| 数据 | 历史数据、参考源 | 清洗、切片建议、候选生成/质量检查 | 领域复核；冻结数据与质量卡 |
| 计划 | 数据、业务标准、负载许可 | 推荐 rubric/指标/负载和成本 | 工程师/审批人；冻结计划 |
| 交付入口 | 已确认请求、获准数据和冻结方案 | 平台直接测为主；可选组装独立 Python 工程 | 导出审批/脱敏/自检；平台无导出也能完成闭环 |
| 效果 | 快照与有界并发 | 共享核心调用、规则/裁判、计数 | 待审任务与完整证据 |
| 复核 | 数据标签/输出争议/抽检/性能异常 | 建任务、分配、对照、受控重算 | 人工决定/必要仲裁；原证据不变，新 assessment |
| 性能 | 独立负载方案/时间窗 | warmup/阶梯/采样/聚合 | 异常时停止；每档指标与瓶颈说明 |
| 决策 | 完整效果/性能/数据证据 | 确定性门禁与报告草稿 | 未过→整改；通过→报告审批 |
| 复测 | 新版本和整改说明 | 同冻结基准重跑、差异分析 | 部分复测不能全量放行 |
| 知识 | 材料/难例/评语 | 脱敏、归纳、候选经验 | 审核后发布，评估后推广 |

项目业务状态：draft → preparing → ready → running → reviewing → accepted → closed；reviewing → remediation → preparing 为整改循环。材料/来源不足留 preparing，运行异常转 reviewing 处理，不自动接受。accepted 需报告审批，不因单运行 PASS 自动触发。closed 是归档动作，不能抹去最终 verdict。
计划状态与数据一致：draft → in_review → approved → frozen → retired；驳回进入新修订。任何变更均使关联旧审批失效。

## 2. 迭代路线（按退出条件，不承诺虚构日期）

| 迭代 | 可交付切片 | 退出条件 |
| --- | --- | --- |
| I0 可信地基 | F01–F09、F13–F14、包部署、能力约束/安全/耐久执行 | 先失败测试后修复；零/全失败/缺指标不 PASS；Docker import、重启/取消、泄密与限额回归 |
| I1a 问答平台闭环 | 项目/提测、cURL 调试/确认、现成数据、冻结计划、双测试、基础复核待办/结果对照、基础报告 | 历史 QA 项目复现；不要求写 JSON/脚本；复核不改原证据；基础整改+全量复测 |
| I1b 独立导出 | 已验证 adapter、共享核心、Python 工程、权限与脱敏 | 干净环境安装/自检、假服务等价、一次受控真实运行；可晚于 I1a 单独发布 |
| I2 数据优先自动化 | 来源导入、候选生成、跨项目复核中心/分配/双盲仲裁、质量卡/盲测、裁判校准、受控外部结果导入 | 新旧数据各一例；无未审核标签混入；人工误放行指标达预设阈值 |
| I3 CV 与报告 | 先图像分类，再按需检测/OCR；用户报告模板映射 | 代表 CV 项目；真实文件/标注切片；模板校验和审批通过 |
| I4 知识与长期回归 | 历史材料迁移、经验推广、复测对比、通知、回滚 | 隔离/删除/污染回归；知识版本变更前后可对照 |
| I5 深度自动化 | 多轮 Agent、可选外部压测器、定时评测、有限自动审批 | 前几阶段稳定，单独风险审查与负载验证 |

数据治理与单条人工复核贯穿 I1a 起；I2 才扩大自动生成，不允许先生成海量低质量数据。整改基础能力进入 I1，通知集成和知识化在后续增强。

## 3. 每个开发切片的工作流

业务验收例 → 契约/API/schema/威胁模型 → 失败测试 → 最小实现 → 单元/集成/界面回归 → 离线历史项目回放 → 人工评审 → 文档/迁移/回退 → 发布。

每项任务包含 owner、需求 ID、修复 ID、代码范围、依赖、测试、验收样例、成本与回退；状态为待办/开发中/待验收/已验收/阻塞，未有证据不得写完成。

## 4. 每轮应看的运营质量指标

数据：有效标签比例、关键切片覆盖、真实/合成比例、标注冲突、泄漏率。
判定：人工一致性、误放行/误拒绝、待审率、裁判不可用率。
流程：材料返工、接入确认后失败率、导出自检/等价通过率、复核待办/逾期/争议率、每条人工时间、完整报告时长、复测可比率。
稳定性：任务中断/恢复、请求错误、发生器瓶颈、预算超限和脱敏失败。

指标只用于发现瓶颈，不把“生成更多用例”当唯一绩效。通过率下降可能是更好覆盖，不自动归咎目标或工具。

## 5. 需要用户提供的试点材料

脱敏清单/报告模板、1 个 QA + 1 个 CV 历史项目、真实 cURL 和成功/错误/流式响应、参考数据授权、人工标签和争议样例、效果门槛、允许并发/时段/成本、整改前后版本。先用小批代表材料校准，不一次导入全部敏感资料，也不把明文 token 放进 Git。

## 6. 自动化逐级开放

- L0：可重复执行；人工导入金标、审批计划/负载，程序跑数和填报告。
- L1：助手检查材料、生成候选、建议规则、解释差异；数据/计划/报告门禁仍由人确认。
- L2：稳定任务使用预批准的模板、冻结数据和负载授权，可自动启动回归/同基准复测；仅异常与抽样复核进入人工队列。

每个自动化授权绑定范围、版本、费用/并发、有效期和撤销人。新任务、新来源、新标签规则、阈值放宽、未批准出站和正式发布不得沿用旧授权绕审。首版不承诺 L3 全无人审核验收；以人工一致性、事故和成本数据决定是否进一步开放。
