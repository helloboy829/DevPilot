# DevPilot 可行性分析 v3.0

> 2026-11-06；文档评审结论，不是上线能力证明。代码基线见[现状审计](DevPilot_现状审计与修复清单.md)。

## 1. 结论

**可行，适合在 DeerFlow 上领域化二次开发，但必须从通用研发助手转为评测业务工作台。**
已有 HTTP 调用、基础效果/性能测试、用户隔离及 Agent 底座可复用；尚无完整提测、数据治理、审批、整改复测和模板报告闭环，不宜无人值守正式验收。

自动化核心是固化已验证的人工流程，而不是让模型临场写脚本后自行宣布通过：

**提测 → 接口调试/确认 → 数据与方案共审 → 平台冻结执行（或受控导出） → 人工复核/效果性能双判定 → 整改复测或报告 → 审核后知识沉淀。**

## 2. 范围与分期

| 阶段 | 场景 | 人工责任 |
| --- | --- | --- |
| 首个闭环 | 一个典型问答组件；HTTP JSON / OpenAI-compatible；已有真实标注 | 授权、标签、容差、负载窗口、报告审批 |
| 第二闭环 | 图像分类；文件上传；正负/难例切片 | 图像授权、标注复核、类别分布 |
| 后续扩展 | 检测、OCR、结构化模型、多轮 Agent、RAG 专项 | 专项指标、环境复位、副作用审批 |

组件类别与任务类型分开：组件是模型或 Agent，任务是问答、分类、检测等。“智能体还是自研模型”不足以选择指标。
不做模型训练平台、自动整改目标模型、公开排行榜、通用研发 SaaS 或无审核的持续学习。

## 3. 技术可行性与边界

| 领域 | 方案 | 风险与前置条件 |
| --- | --- | --- |
| 接入 | cURL → 版本化 RequestSpec，调试/平台/导出共享确定性核心 | 不执行 shell；签名/回调/multipart 不支持时明确阻断 |
| 数据 | 历史真实数据优先，合成为补充，复核后冻结 | 样例不代表总体；全合成不能证明线上质量 |
| 效果 | 规则/专项指标优先，语义裁判校准，争议人工审 | 裁判偏差、泄漏、小样本和类别失衡 |
| 性能 | 有界负载 Worker，统一时间/token 口径 | 非流式无可观测 TTFT；客户端吞吐不等于服务端算力 |
| 自动化 | DeerFlow 工具编排 + 可恢复业务任务 | 对话不是业务真相源；限制预算、循环与重试 |
| 知识 | 版本化材料、案例、规则及检索 | 记忆污染、跨项目泄漏和敏感数据出域 |

参考 LLMPerf 的并发、延迟和吞吐方法，而不照搬其测试文本和 tokenizer；方法参考不等于已完成集成。官方资料见[技术依据](DevPilot_技术依据与决策记录.md)。

## 4. DeerFlow 是否过重

保留认证、Gateway、模型工厂、工具/Skill、LangGraph、沙箱和追踪。聊天首页、博客、展示站、语音、IM、定时任务、通用 Agent 管理先隐藏或按部署能力关闭。
**隐藏 → 依赖验证 → 回归 → 再删除**。不能为轻量破坏鉴权、存储、流式或上游合并能力。

## 5. 可信评测成立条件

提测方应提供可调用接口、合法参考材料、业务口径和可复核预期。只有一个 cURL 和两条样例时可接入 PoC，但不能正式验收。
以来源覆盖、风险分层、重复/泄漏检查、标签一致性、冻结盲测和置信区间建立证据。实际阈值由双方审批，不默认所有项目同一准确率。

## 6. 成本与持续维护

不采用未经验证的市场规模、利润或固定 token 报价。试点实测：导入/标注/复核工时、每条有效标签成本、返工率、生成/裁判 token、目标接口费用、压测和存储成本、报告时间、错误放行代价。

项目成本 = 人工审核 + 目标调用 + 生成/裁判 + 基础设施 + 运维。每项目/每运行预算事前估算，事后核算。先回放历史项目与人工结论对照，再决定扩大投入，不预承诺节省比例。

## 7. 投资与扩展门槛

- G0：假 PASS、安全、打包阻断修复，失败与缺证据不放行。
- G1：历史问答项目可复现，数据与报告获人工评审认可。
- G2：图像分类项目闭环，文件、标注和切片获认可。
- G3：整改复测、知识推广与回滚可演示，隔离/恢复/成本可控。

未达门槛不扩大无人值守范围；材料无法合法获得时只做接入/性能试验，暂停效果验收。

## 7. 最新交互意见的可行性与取舍

- 类 Postman 调试入口可行，价值是降低接入/定位成本；仅做评测需要的 HTTP JSON、流式与后续 CV 文件适配，不重造通用 API 开发工具。调通证据与压测授权分开。
- 平台内直接评测是主链，导出可独立运行的 Python 工程是附加交付。共享核心/受控模板比“Agent 每次自由写脚本”更可维护；依赖、数据授权、裁判可用性与干净环境测试是导出前提，不承诺任意 cURL 自动兼容。
- 人工复核不是后置补丁：I1 就有逐条 Q/A/expected/来源对照，I2 再扩双审、仲裁和跨项目分配；不能为了自动化吞掉待审项。
- TTFT 仅在文本生成流式调用已启用且首内容增量可观测时测；只有进度流或完整响应不满足本项目定义。
- 只维护中文/英文项目文档，减少重复维护；不因此删除底座运行模块、许可证或限制评测材料语言。
