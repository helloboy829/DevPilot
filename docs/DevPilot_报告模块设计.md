# DevPilot 报告模块设计与实施边界

> 2026-11-07。报告是独立业务模块，不是让模型凭聊天记录自由编写的文档。本版提供**人工填报的无状态草稿**；正式报告归档、模板管理和审批属于后续设计。

## 1. 需求与流程

目标流程：选择项目/组件版本 → 引用冻结的平台结果，或人工填报 → 校验事实与统计口径 → 选择已发布的模板版本 → 生成草稿 → 人工复核/审批 → 固化快照并发布 → 整改后产生新修订。

报告入口与评测结果页可以共享同一业务服务。允许先填报历史结果，并不表示这些结果已经被平台实测核验。效果不通过、数据不完整、摸底评测也能生成记录，但不得生成“验收通过”的暗示。

来源应按字段区分：

- `platform_observed`：指向有权限访问的不可变 run/result revision，并可追溯逐条证据。
- `manual_unverified`：人工填写的事实，只能证明有人填报，不能证明结果真实。
- `reviewed_external`：外部结果经授权人员复核并关联证据，不等价于平台实测。
- 混合来源不可被一个“已核验”布尔值覆盖；人工覆盖平台值需记录原值、理由、人员与时间。

**当前仅实现 `manual_unverified`，不接受客户端指定来源、核验标志、生成身份或审批状态。**

## 2. 当前可用的最小切片

页面：`/workspace/reports`，侧栏“报告 / Reports”。不替换旧的 component-tests 报告接口。

1. 获取内置中英模板目录，选择明确的 ID 与版本；无 `latest` 隐式回退。
2. 填写报告标题、项目/组件/版本、测试人员与时间范围、环境、范围、统计方法、证据说明和限制。所有文字必填；不适用时必须由人明确说明，系统不虚构内容。
3. 选择效果、性能或两者。输入默认留空，不预置客户结果或看似真实的测量值。
4. 确定性校验计数和适用性，由程序计算通过率/调用成功率。
5. 生成标注 DRAFT、人工填报未核验、未经审批的草稿，预览 Markdown 源文。
6. 下载 Markdown 或 JSON。JSON 带事实、模板完整快照及 manifest；Markdown 带版本、hash 与生成信息。

当前不保存服务端报告、不写浏览器持久存储，不把表单放 URL/聊天上下文。下载由浏览器内存生成，文件名固定；响应与请求禁用缓存。表单修改、模板版本/界面语言切换即清除旧预览和下载；生成期间禁用编辑，忽略已失效的异步结果。离开页面前需下载，否则输入不会自动恢复。

### 当前指标契约

- 效果：`total = passed + failed + errors + pending + not_run`，均为整数，`total > 0`。主通过率严格为 `passed / total`，不能排除待审/未跑后提高比例。二值通过率不是加权得分，也不自动等同于有充分金标支撑的准确率。
- 性能：`requests > 0`、`concurrency > 0`，成功数不得超过总数；调用成功率为成功数/总数。
- 延迟：明确 `metric_population` 为成功请求、全部尝试或失败尝试。填均值时，`latency_sample_count` 必须等于所选总体的计数，不能用成功子集冒充全量。
- TTFT：只有测试时声明启用且能测得首个有效内容 token/增量的流式能力才适用；首字节、握手、空事件不是 TTFT。当前人工表单仅校验声明与成功样本覆盖，**不能自动证实采集语义**。可记录成功请求子集，但须同时展示样本数，禁止据此自动验收。
- TPS：本版字段代表测试时间窗内整体输出 tokens/s，不是请求速率或每请求平均 token 速度。必须选择 provider usage、tokenizer 或 estimate，并在方法中说明输出 token 定义、时间窗与失败处理；无 token 来源不能填 TPS。estimate 不伪装为精确值。
- 缺失指标是 `null`、未测量/不适用，不补零。非负有限数，布尔值不冒充数值。计数上限为工程输入约束，不是验收门槛。
- 平均响应时间/TTFT 单位 ms；吞吐单位 tokens/s。P95/P99、QPS、多负载档、加权评分与阈值判断尚未接入本版事实 schema，不能塞入已有字段假装受支持；确需说明可填方法/限制，后续以新 schema 支持。
- `BASELINE`/`ACCEPTANCE` 仅标记填报目的。草稿没有自动 verdict，不执行阈值审批，不会因选择 ACCEPTANCE 自动通过。

## 3. API 与代码边界

| 接口 | 权限与行为 |
| --- | --- |
| `GET /api/reports/templates` | 登录 + `threads:read`；返回已内置模板 ID/version/language/name/schema_version |
| `POST /api/reports/preview` | 登录 + `threads:write`；显式 template_id/template_version/facts，返回草稿，业务校验失败 422 |

第一阶段暂复用现有权限，与 component-tests 一致，不表示已有项目级报告授权。后续归档前必须新增 `reports:read/write/review/publish`、模板管理权限以及 owner/project 授权检查。

`devpilot.reporting` 负责纯事实校验、内置模板目录、快照、hash 与 Markdown；不调用模型、不访问目标接口、不读写文件，也不依赖 DeerFlow。Gateway 负责认证、生成者与 UTC 时间，前端使用现有带凭据/CSRF 的 fetch 封装。无数据库迁移、无持久任务、无模板上传执行器。

manifest 包括 `schema_version`、`renderer_version`、`template_id/version`、事实和模板的 SHA-256、服务端生成者和时间。hash 基于 UTF-8 规范 JSON（键排序、紧凑分隔、不允许 NaN）。**hash 用于内容比对，不是签名、不可篡改证明、事实真实性或审批凭证。**重新生成时间会变化；不承诺下载 JSON 字节级完全相同。

## 4. 模板更新：版本不覆盖

目标模板状态：`DRAFT → VALIDATED → PUBLISHED → DEPRECATED`。已发布版本只读；修正文字、字段映射、样式或指标公式均发布新版本，不能修改原版本。旧报告始终引用原模板版本、内容 hash、renderer 版本、schema 版本与输入事实快照，不随默认模板更新而改变。

- 模板目录可推荐新版本，但用户确认后才升级新草稿。
- 使用新模板重新出具须创建新 report revision，关联原报告，不原地改旧文件。
- renderer 也版本化；新 renderer 不能被默认为可重现旧排版。正式版保存实际产物字节及 hash，必要时保留旧 renderer 的可运行制品。
- 模板停用阻止新用，不删除历史引用。严重错误用撤回/更正事件说明，不能抹去历史。
- 字段 schema 不兼容时先迁移预览、明确缺项；禁止静默补零、套错字段或让模型填必需证据。

本版只有内置 `component-evaluation-zh/en@1.0.0` 的显式固定与快照，没有模板状态管理页面、上传/编辑、默认版本配置和历史版本数据库。后续新增版本时保留旧目录项与兼容测试。

## 5. 草稿修订、复核与发布（待实现）

建议状态：`DRAFT → IN_REVIEW → APPROVED → PUBLISHED`，另有 `CHANGES_REQUESTED / SUPERSEDED / WITHDRAWN`。人工复核报告事实不替代逐条结果复核；二者共享证据引用但分别审批。

- 任意影响事实、范围、模板、结果或结论的编辑都创建修订，并使旧审批失效。
- 提交复核前冻结事实/模板快照，校验计数、缺失、单位、来源、权限及证据可达。
- 复核页面左右对照本次/上次，突出指标、样本范围和结论变化；可直接跳转待审案例和引用证据。
- 人工审阅、系统自动判断、发布动作分离；发布必须服务端校验被批准的精确修订与 artifact hash，不能相信前端按钮禁用。
- 用户可以显式记录人工结论及理由，但不可改写原始观测；审批不修饰成自动通过。
- 并发编辑用 revision/ETag 乐观锁；重复发布用幂等键与唯一约束。撤回保留原记录及审计链。

当前仅有内存草稿，不具备上述修订/审批/审计保证；下载文件由使用者保管。

## 6. 持久化与导出设计（待实现）

沿用 App 业务层与现有 SQLAlchemy/Alembic，不把报告业务塞入 harness。建议增加：

| 实体 | 关键字段/约束 |
| --- | --- |
| report_template | owner/scope、模板标识、用途；共享需授权 |
| report_template_version | 唯一 template_id+version，状态、字段映射、schema、内容 hash、验证记录，发布后不可变 |
| report / report_revision | owner/project、report_id+revision 唯一、冻结事实/来源、template/renderer/schema、parent、状态、审批对应 revision hash |
| report_artifact | revision、格式、受控对象引用、实际文件 hash、大小、导出状态 |
| report_review / audit_event | actor、动作、理由、前后版本/hash、时间；限制可见性，不含凭据正文 |

落地顺序：先增量迁移和最小权限 → 草稿 CRUD/来源引用 → 修订与审批事务 → 异步导出与归档。回滚不删除已发布证据；发布中禁止旧服务绕过新版门禁，保留受控只读导出路径。上线前测试数据库升级/降级策略、跨 owner 拒绝和并发审批冲突。

DOCX/PDF 后续由同一冻结事实渲染，不能另起模型重新算数。导出 Worker 限时、限内存、限页数/输出大小，无任意网络权限；任务恢复和重复生成须幂等。模板上传先隔离、限制类型/体积/展开比、拒宏和外部链接，不执行 Office 脚本，不允许任意 Python/Jinja 表达式/文件系统读取。先做占位符 allowlist、字段映射校验、合成样张比对，再批准新版本。

## 7. 脱敏与知识库边界

真实名称、场景、历史汇总指标、测试时间窗、内部地址、金标、原始报告和凭据不进 Git。公开设计只保留通用流程；测试 fixture 为独立合成示例，不能从客户数字改名得来。脱敏不仅改最新文件，也检查待上传提交祖先；已公开敏感信息需单独评估历史清理和凭据轮换，不能保证新提交能撤回既有泄漏。

本版模板是通用布局，不复制客户原报告。报告生成不调用外部 LLM。将正式报告沉淀到知识库时另行授权/脱敏/审核；验收答案不进通用记忆或被测目标上下文。下载件可能含用户填写的敏感事实，不应自动提交仓库。

## 8. 验收与下一步

当前验收：合法输入生成 DRAFT；计数不一致拒绝；非流式 TTFT 拒绝；缺失非零；固定模板版本及快照；生成身份服务端绑定；认证/只读权限生效；HTML/Markdown 结构转义；表单/版本修改后旧下载失效；空模板/接口错误可见。单元与 mock 浏览器测试不代表客户报告已核验或生产部署已验收。

后续优先：先补评测执行安全/可恢复性门禁，再在报告模块接入有权限的平台结果与持久化修订。拿到**脱敏空白报告模板**后做字段映射与样张确认，随后模板管理、人工审批、DOCX/PDF。没有授权不上传真实报告去自动“学习”。
