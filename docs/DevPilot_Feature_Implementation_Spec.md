# DevPilot 功能实现说明与模块验收矩阵

更新：2026-11-19。本文件把业务功能映射到当前代码、API/数据边界和可执行验收切片。**当前实现事实**以[交付状态](DevPilot_Delivery_Status.md)为准；**开发进度和先后顺序**以[实现进度与下一步](DevPilot_实现进度与下一步.md)为准；本文件不替代领域合同，不以代码存在或测试通过单独证明产品闭环。

## 状态词义与实现规则

| 状态        | 含义                                                                        |
| ----------- | --------------------------------------------------------------------------- |
| 已实现      | 源码存在并有对应模块/测试；是否部署、是否完成真实用户验收仍以交付状态为准。 |
| 部分实现    | 只覆盖表内列出的基础流程；下列缺口仍阻止完整业务闭环。                      |
| 待开发      | 当前没有可用于该目标流程的生产代码；文档 schema/API 是目标合同。            |
| 兼容/待迁移 | 现有入口继续读写既有路径；新能力不得继续扩大旧路径的职责。                  |
| 候选        | 代码或离线验证存在，但未完成当前 SHA CI、部署或业务验收。                   |

每个开发切片先添加能失败的单元/API/迁移/UI 回归，再实现最小纵切面。状态须由代码、测试结果、准确 SHA 的 Actions 和部署/业务验收分别支持；unknown、skipped、定向补测和历史通过数不得合并成全绿。数据库变更只追加迁移，API 使用严格 DTO，UI 用户动作显式授权；任何真实目标调用、数据外发、敏感明文访问和部署继续遵守单独授权合同。

## 9. 代码与文档偏差的重构原则

1. 新效果/性能能力以 `app.evaluation` durable identities 和共享 `devpilot` QA core 扩展；不把 Agent、Gateway event loop 或旧 `/component-tests` scheduler 用作压测核心。
2. 现有 `EvaluationReviewPanel` / `/review-runs` 继续作为兼容人审路径；新结果页增加只读结果 DTO、游标查询和独立 evidence access，迁移期间不得双写不同 verdict。
3. `evaluation_output_evidence` 的 encrypted extracted text 保留原样。新增原生 response/request artifact 与 `capture_status`；历史 run 标记 `unavailable_legacy`，不得用提取文本伪装 raw HTTP body。
4. 可选 expected 与原始响应在同一演进方案内协调迁移，但彼此采用不同 API field、hash 和访问权限；旧冻结数据 revision 不改写。
5. legacy route 最后渐进停止新写入；新 route 覆盖已部署/候选合同并通过 migration/API/UI parity 后才将 legacy 限定为只读，不能先删数据或入口。
