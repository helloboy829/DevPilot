# 历史材料分析与产品设计校准（公开脱敏版）

> 本文仅保留可复用的方法与设计约束。项目/客户/行业名称、原件路径、组件及样本数量、评分、耗时、负载、运行日期、版本差异数量和逐条结果均不发布，也不使用可反推原项目的别名对应表。未执行原材料中的脚本或请求接口。下述内容是设计依据，不代表对应功能已经实现。

## 1. 总体判断

评测自动化可行，但可信度取决于授权参考源、审核金标、指标口径、运行证据和报告可追溯性，而不是让 Agent 自动调用接口。历史交付材料可用于校准流程，但不能直接视为已审验收数据集。

先选择参考源明确的问答或结构化任务跑通闭环，再扩展预测、CV 和多轮 Agent。数据不足时应先补参考结果，不应批量生成没有审核依据的样本。

## 2. 提测清单与任务分类

- 导入保留组件版本、功能/需求映射、字段说明、来源、每组件负载与批准标准。按有效记录计数，不按序号最大值计数。
- 请求样例、候选预期、审核金标、参考模板和运行记录属于不同资产；文件存在不等于内容齐全。
- 规则计算应使用经确认的公式、单位、边界与容差作为独立 oracle；文案使用事实、关键要点及安全约束 rubric，不要求逐字匹配。
- 不同任务分别选择评估器，不为所有模型或智能体套用同一问答判分器。
- 时间变化的数据源须绑定 as_of、时区、批次/快照与证据。无法保留原始数据时登记原因及可验证摘要。
- 有外部写入副作用的组件需要测试租户、幂等、复位和额外压测授权；调通接口不等于授权重复写入。

## 3. 数据版本与效果判定

- 数据集修订不是独立样本累加；同一集合多次运行也不增加独立样本数。保留版本差异与每次 attempt，不能选择最好一轮代表整体。
- 传输成功、业务成功、结果有效、任务正确必须分别记录；HTTP 成功不等于答案正确。
- 结构、日期和数值格式合格只能证明输出契约合法，不能证明预测值准确。contract_valid 与 value_verified 分开；没有真值时效果准确率不可用。
- 预测使用独立真实值与历史回测，按预测时点隔离未来信息；明确预测跨度、锚定时点、缺失和零值策略。另一模型的输出只能支持一致性分析，不能充当实际真值。
- 验收分母来自冻结的数据集，待审、未执行及失败不得静默隐去。二值通过率与加权/分档评分分开，不将评分写入通过率字段。
- 负例必须匹配预期错误类别或约束；基础设施故障不能冒充正确拒绝。
- 范围调整须在运行前审批，不能按失败结果挑选简单样本。动态“最新批次”描述必须落成确定快照。

## 4. 性能与报告口径

- 每个组件/运行分别冻结负载、预算与阈值，不静默套统一默认验收标准。
- 区分成功、全部及失败请求的耗时统计，保留计数、单位与 metric_population。
- TTFT 仅适用于支持并实际启用内容流式输出的调用；状态事件或连接建立不冒充首个有效内容。
- 无批准标准的摸底使用 BASELINE，只输出观察值和限制，不得发布验收通过结论；ACCEPTANCE 必须冻结批准方案。
- 报告包括依据、环境、版本、范围、指标定义、证据、限制和签审，而不只有几个汇总数字。

## 5. 报告模块的设计方向

报告是独立业务模块，允许人工填写、引用平台结果或混合来源；手填数据必须标明来源、填报人与证据，不伪装成平台实测。

事实模型与模板分离，模板更新产生新版本。草稿修改产生新修订；生成产物绑定数据快照、模板版本和渲染器版本，不因默认模板改变而覆盖历史报告。缺少必要事实不得让模型补写。

数值校验、判定、审批和报告渲染分别负责；模板只控制呈现，不能改变分母或把摸底变成验收。修改数据、映射或模板后，旧产物不被偷偷更新，正式发布须重新审批。

## 6. 知识沉淀与公开边界

来源材料、候选案例、审核金标、运行证据和规则/Prompt 分级存储；授权、脱敏、去重、审核后才能推广使用。原件、答案与凭据不进公开仓库或普通模型记忆。

公开文档只描述通用方法，禁止发布真实项目名称及任何客户汇总结果。代码测试使用明确虚构的示例；工程 CI 的通过数量属于本仓库验证记录，不是客户评测指标。
