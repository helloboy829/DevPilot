# DevPilot · AI 组件评测工作台

[English](README.md) · [设计与开发文档](docs/README.md) · [本轮交付与配置](docs/DevPilot_Evaluation_Workspace.md)

DevPilot 基于 ByteDance DeerFlow 的 Agent 底座二次开发，面向 AI 模型、CV、LLM 和 Agent 的效果与性能评测。产品界面使用 DevPilot；`deerflow` Python 包、兼容 API、既有环境变量与上游版权保留，避免破坏底层升级和存量数据。

> 当前是可体验的开发版本，不是完整的无人值守验收系统。平台事实、模型建议和人工决定必须分开；不能因为接口返回成功就判定组件效果通过。

## 本地使用

完整服务的统一入口为 `http://127.0.0.1:2026`。新环境按 [Install.md](Install.md)、根目录 `AGENTS.md` 和模块指南安装；可使用 `make dev` 或 Docker。凭据、运行配置和业务材料不要提交 Git。

| 入口 | 当前能力 |
| --- | --- |
| 组件测试 `/workspace/component-tests` | 注册组件、初版效果/性能执行；新增完整 cURL 粘贴、解析、编辑、单次发送、查看/复制响应 |
| 定时评测 `/workspace/evaluation-schedules` | 单次/cron/时区、冻结参数、暂停/恢复、执行历史；直接进入确定性评测器，不生成聊天或推送任务 |
| 报告 `/workspace/reports` | 人工填写指标、单组件及项目多组件快照、固定版本中英文模板、Markdown/JSON 草稿下载 |
| 模型与分工 `/workspace/models` | 管理员添加/编辑/删除模型、显式连接测试、加密且只写的 API Key、角色分配 |
| 聊天 | 保留底座会话与单次模型选择，供有界 Agent 协作，不代替评测事实账本 |

### cURL 调试

粘贴一条完整命令，点击“解析 cURL”，检查方法、URL、请求头和请求体，授权后发送。不执行 Shell、不读取命令中指定的本地文件，不绕过 TLS；目标须由管理员批准。支持常见 JSON/body/header/basic-auth 选项和常见行续接。

这不是完整 Postman：暂不支持 multipart 文件/图片上传、Cookie jar、集合/环境管理、前后置脚本、自动跳转、测试脚本导出；调试结果也尚未自动成为已批准的评测请求版本。调试内容仅在当前页面内存中，不保存历史。

### 定时评测

适合避开高峰执行效果采集、性能压测。后台必须设置 `scheduler.enabled: true`，并批准目标域名。保存前确认组件、参数、样本、时区和负载；组件关键配置变更后旧计划拒绝执行，需重新确认。运行时重新检查用户与执行权限，不将凭据复制到计划。

当前效果调度只采集并保留待人工复核结果，不自动向裁判模型发送返回。性能计划有请求量、并发和超时限制。复用调度器的租约、历史和防重叠能力，但组件执行仍是进程内任务，尚不是完整耐久 Worker 队列。暂停/删除不等于终止已经开始的运行。

### 多组件报告与 Agent

先填写一个组件的真实结果，点击“加入项目”，再填写下一组件。各快照必须属于同项目/测试人/周期/模式；各组件独立统计，不把不同组件准确率或延迟简单平均。快照不随下方表单编辑自动变化，需移除重加。离开页面前下载，当前没有服务端报告保存和正式审批。

模板参考授权历史报告的通用章节结构，**不包含原始客户名称、历史指标或报告原文，不是原 DOCX 版式复刻**。模板按 ID+版本固定；未来更新新增版本，不覆盖已出具版本。

可选报告 Agent 复用 DeerFlow 模型工厂和 LangGraph：输入需求 → 返回字段建议/待确认问题 → 人工确认 → 填写真实指标 → 生成草稿。当前是单轮结构化需求整理，尚非持久多轮对话。另有仅发送汇总指标的解释助手，两条路径均需显式同意。模型不能补测量值、修改分母、批准报告或把建议变成测试事实。

### 模型配置

管理员先为 Gateway 设置 `DEVPILOT_MODEL_CATALOG_DIR` 到独立持久私有目录，重启后可在页面配置 OpenAI-compatible 或 Anthropic 模型。API Key 不回显，留空保留旧值；整个目录数据库加密，密钥通过 `DEVPILOT_MODEL_ENCRYPTION_KEY` 提供，或自动生成独立 `catalog.key`。生产使用独立密钥管理，并保护密文和密钥备份、Windows ACL。

- `general_agent`：通用 Agent 默认模型；会话仍可单次切换。
- `report_advisor`：需求整理与报告建议；绑定后启用，调用前仍需同意。
- 数据构建、效果裁判、复核助手：目前仅预留角色配置，尚未接通完整流水线。

工作模型与被测组件分开管理。没有配置真实模型时仍可调试接口、人工填报；报告 Agent 会明确不可用，不静默回退。

## 目标业务闭环与后续优先级

提测清单 → 接口调试/确认 → 数据来源授权、构建与审核 → 冻结数据和方案 → 执行效果/性能 → 人工复核 → 整改复测或审批报告 → 审核后知识沉淀。

1. 数据集版本、金标/来源/切片/去重/防泄漏与审核是下一阶段首要工作。
2. 冻结请求规范与评测适配器统一，真实可用的独立测试工程导出。
3. 结果人工复核中心、证据回链、持久报告与模板修订/审批。
4. 耐久执行队列、配额/取消、全路径 TLS/出站策略与审计。
5. 有依据的裁判模型接入及经审核知识闭环；不自动训练、不让验收答案污染知识。

效果通过率为通过数/总数，错误/待审/未执行不丢失。非流式不适用 TTFT；只有可观测文本内容增量的流式调用才测客户端 TTFT。缺失指标不能当作零或自动通过。

## 开发与验证

后端先测试再修改，并运行 Ruff 格式化/检查；前端通过 `scripts/pnpm.py` 调用 pnpm，运行 `check`、单测与浏览器测试。本轮测试只使用合成数据和 mock 模型/接口，真实目标和模型配置后的兼容性仍须另行授权验证。
