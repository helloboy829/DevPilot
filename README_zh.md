# DevPilot · AI 组件评测工作台

[English](README.md) · [设计与开发文档](docs/README.md) · [本轮交付与配置](docs/DevPilot_Evaluation_Workspace.md)

DevPilot 基于 ByteDance DeerFlow 的 Agent 底座二次开发，面向 AI 模型、CV、LLM 和 Agent 的效果与性能评测。产品界面使用 DevPilot；`deerflow` Python 包、兼容 API、既有环境变量与上游版权保留，避免破坏底层升级和存量数据。

> 当前是可体验的开发版本，不是完整的无人值守验收系统。平台事实、模型建议和人工决定必须分开；不能因为接口返回成功就判定组件效果通过。

## 工作台外观与导航

侧栏固定为“评测中心 / 智能协作”两组，进入“对话”或“自定义助手”不再突然插入顶部“新对话”导致菜单跳动。新建对话在对话列表页或命令面板操作；管理助手不会自动新建对话。

**设置 → 外观 → 工作台风格** 提供“精密控制台、石墨极简、森林实验室、暖纸工作室、紫罗兰工坊”五种风格，均可搭配浅色、深色和跟随系统。偏好仅保存在当前浏览器，不是账号设置，不涉及评测事实；支持键盘操作与移动端。[边界和 CI 验证记录](docs/DevPilot_Workspace_Styles_CI.md)。

## 助手开放与请求模板

自定义助手现在默认向**所有已登录用户**开放，不限管理员。各账号管理自己的助手和私有资料，管理员仍可通过 `agents_api.enabled: false` 关闭。旧全局 `USER.md` 原样保留，不通过个人资料接口展示或覆盖；实际模型对话仍需接入可用模型，启用助手管理并不会自动配置模型。

cURL 调试器新增“**导出参数化请求模板**”：生成 `request-template.v1` JSON 和结构 SHA-256 指纹。完整 URL（含路径/查询）、全部请求头值和请求体均替换为运行时引用；仍保留方法、来源主机/协议/端口及请求头名，应将这些元数据也纳入保密审查。该下载仅为配置契约，不是服务端保存的请求版本、可执行脚本、目标授权、调通证明或评测证据。详见[本轮交付与边界](docs/DevPilot_Assistants_Request_Templates.md)。


## 项目组件与提测清单

“项目与数据”支持一个项目关联多个本人已登记组件，每个组件保存多个不可变清单版本，绑定同项目冻结 QA 的 revision/hash。服务端只取必要库存字段，不复制接口密钥或金标。它不是可执行计划、验收通过或报告证据；详见[实现边界](docs/DevPilot_项目组件与提测清单.md)。

## 本地使用

完整服务的统一入口为 `http://127.0.0.1:2026`。新环境按 [Install.md](Install.md)、根目录 `AGENTS.md` 和模块指南安装；可使用 `make dev` 或 Docker。凭据、运行配置和业务材料不要提交 Git。

| 入口 | 当前能力 |
| --- | --- |
| 评测工作台 `/workspace/evaluations` | 默认首页，展示真实组件库存、评测步骤和未实现能力；不虚构验收统计 |
| 组件测试 `/workspace/component-tests` | 注册组件、初版效果/性能执行；新增完整 cURL 粘贴、解析、编辑、单次发送、查看/复制响应 |
| 项目与数据 `/workspace/datasets` | 本人项目、多组件关联与不可变提测清单、来源/授权声明、JSON/JSONL导入校验、Q/预期/来源并排检查和确认冻结 |
| 定时评测 `/workspace/evaluation-schedules` | 单次/cron/时区、冻结参数、暂停/恢复、执行历史；直接进入确定性评测器，不生成聊天或推送任务 |
| 报告 `/workspace/reports` | 人工填写指标、单组件及项目多组件快照、固定版本中英文模板、Markdown/JSON 草稿下载 |
| 模型与分工 `/workspace/models` | 管理员添加/编辑/删除模型、显式连接测试、加密且只写的 API Key、角色分配 |
| 聊天 | 保留底座会话与单次模型选择，供有界 Agent 协作，不代替评测事实账本 |

### 导航与统一执行防线

评测页面只保留一个“组件测试”导航入口。原“智能体”明确为“自定义助手”：默认向所有已登录用户开放，管理员显式关闭时隐藏入口，不再留下置灰入口；它不代替评测执行器、报告助手或人工验收。调试、手动效果/性能、定时评测共用目标白名单、DNS 固定及 TLS 校验；空白名单也会阻止手动测试。详见[导航与统一出站基线](docs/DevPilot_导航与统一出站基线.md)。

### cURL 调试

粘贴一条完整命令，点击“解析 cURL”，检查方法、URL、请求头和请求体，授权后发送。不执行 Shell、不读取命令中指定的本地文件，不绕过 TLS；目标须由管理员批准。支持常见 JSON/body/header/basic-auth 选项和常见行续接。

这不是完整 Postman：暂不支持 multipart 文件/图片上传、Cookie jar、集合/环境管理、前后置脚本、自动跳转、测试脚本导出；调试结果也尚未自动成为已批准的评测请求版本。调试内容默认仅在当前页面内存中，不自动保存历史；只有在请求版本弹窗明确确认后才加密保存完整请求定义。

### 定时评测

适合避开高峰执行效果采集、性能压测。后台必须设置 `scheduler.enabled: true`，并批准目标域名。保存前确认组件、参数、样本、时区和负载；组件关键配置变更后旧计划拒绝执行，需重新确认。运行时重新检查用户与执行权限，不将凭据复制到计划。

当前效果调度只采集并保留待人工复核结果，不自动向裁判模型发送返回。性能计划有请求量、并发和超时限制。复用调度器的租约、历史和防重叠能力，但组件执行仍是进程内任务，尚不是完整耐久 Worker 队列。暂停/删除不等于终止已经开始的运行。

### 多组件报告与 Agent

先填写一个组件的真实结果，点击“加入项目”，再填写下一组件。各快照必须属于同项目/测试人/周期/模式；各组件独立统计，不把不同组件准确率或延迟简单平均。快照不随下方表单编辑自动变化，需移除重加。离开页面前下载，当前没有服务端报告保存和正式审批。

模板参考授权历史报告的通用章节结构，**不包含原始客户名称、历史指标或报告原文，不是原 DOCX 版式复刻**。模板按 ID+版本固定；未来更新新增版本，不覆盖已出具版本。

可选报告 Agent 复用 DeerFlow 模型工厂和 LangGraph：输入需求 → 返回字段建议/待确认问题 → 人工确认 → 填写真实指标 → 生成草稿。现支持带前文的可见多轮需求对话（最多 10 轮、序列化上下文 24000 字符），每轮重新同意外发；仅页面内存，离开不恢复，并非持久会话。另有仅发送汇总指标的解释助手，两条路径均需显式同意。模型不能补测量值、修改分母、批准报告或把建议变成测试事实。

### 模型配置

管理员先为 Gateway 设置 `DEVPILOT_MODEL_CATALOG_DIR` 到独立持久私有目录，重启后可在连接档案页面配置 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini Developer API；服务商标签、地址和模型 ID 可自定义，支持预设、搜索、复制档案和白名单高级参数（采样、输出上限、超时、重试）。这借鉴 CC Switch 的连接管理思路，不等于完整兼容其客户端/OAuth/代理能力。API Key 不回显，留空保留旧值；更换地址或协议必须重填或明确清除旧密钥，复制档案不复制密钥；整个目录数据库加密，密钥通过 `DEVPILOT_MODEL_ENCRYPTION_KEY` 提供，或自动生成独立 `catalog.key`。生产使用独立密钥管理，并保护密文和密钥备份、Windows ACL。

- `general_agent`：通用 Agent 默认模型；会话仍可单次切换。
- `report_advisor`：需求整理与报告建议；绑定后启用，调用前仍需同意。
- 数据构建、效果裁判、复核助手：目前仅预留角色配置，尚未接通完整流水线。

工作模型与被测组件分开管理。没有配置真实模型时仍可调试接口、人工填报；报告 Agent 会明确不可用，不静默回退。

### 项目与 QA 数据

创建本人项目和数据版本，登记授权来源后粘贴 JSON 数组 / JSONL（最多500条、500000 UTF-8字节），校验成功才整批保存。主动查看问题、预期答案与来源，人工确认后冻结；修改须另建版本。金标单独存储、单独授权读取，普通列表不返回答案，页面不写浏览器持久缓存或聊天。持久数据库未启用时返回不可用，不能默默丢数据。

当前允许本人自审，**不是独立双人审核或验收通过**；来源授权是用户声明，平台不自动核验。未调用数据生成Agent，也未把冻结数据接入组件/测试/报告。完整边界见[QA数据最小闭环](docs/DevPilot_QA数据最小闭环.md)。

## 目标业务闭环与后续优先级

提测清单 → 接口调试/确认 → 数据来源授权、构建与审核 → 冻结数据和方案 → 执行效果/性能 → 人工复核 → 整改复测或审批报告 → 审核后知识沉淀。

1. 在QA版本最小闭环上接通提测/组件版本与执行引用，补独立审核、质量卡、跨集泄漏和结果复核。
2. 冻结请求规范与评测适配器统一，真实可用的独立测试工程导出。
3. 结果人工复核中心、证据回链、持久报告与模板修订/审批。
4. 耐久执行队列、配额/取消、全路径 TLS/出站策略与审计。
5. 有依据的裁判模型接入及经审核知识闭环；不自动训练、不让验收答案污染知识。

效果通过率为通过数/总数，错误/待审/未执行不丢失。非流式不适用 TTFT；只有可观测文本内容增量的流式调用才测客户端 TTFT。缺失指标不能当作零或自动通过。

### 手动配置评测助手

所有已登录用户均可通过 **自定义助手 → 手动配置助手** 保存个人助手，无需先调用模型。提供需求梳理、数据设计、结果复核三类中英文预设；真实对话仍需可用模型。预设不是隔离的评测执行器，也不出具正式验收结论，报告生成仍从报告模块进入。

### 加密请求定义版本

本人项目/组件可通过 API 保存只追加请求版本，完整 URL、全部头值和 body 使用独立运维密钥认证加密，读接口仅返回结构元数据。新增 App 迁移 `eval_0003`，不修改已部署迁移。组件调试器已提供「保存请求版本」与无需导入即可使用的「查看请求版本」，支持项目/组件选择、独立的加密存储确认与元数据查看；保存不发送网络请求。它不是凭据引用仓库、执行批准、调通证明或报告证据。需要显式配置 `DEVPILOT_REQUEST_ENCRYPTION_KEY`，本轮不改既有本地配置；详见[范围和操作边界](docs/DevPilot_Request_Versions.md)。

请求版本的操作、失败恢复与后续冻结计划/Worker 边界见 [UI 交付说明](docs/DevPilot_Request_Version_UI.md)。
